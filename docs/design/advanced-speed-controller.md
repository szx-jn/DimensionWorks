# 高级转速控制器

## 定位与进度

第二项齿轮之心诅咒解除后，自有 Create 网络合计 4,096 SU 的容量额度解除。高级转速控制器定位为此阶段的精确调速工具，不使用配方解锁、任务检查或诅咒状态检查，也不承担修复碎片的能力考核。

当前第二项碎片仅由铁板与黄铜板压块获得，没有独占材料。因此本配方通过配套生产链形成软门槛，不能严格禁止提前制作；严格材料门槛需要先设计并审核阶段独占材料，不能把未确认的碎片能力分配当作既定事实。

## 5×5 动力合成

本配方按 [ME 实时应力与造价调整](me-live-stress-network.md) 使用两条路线共同的中后期材料门槛。

25 个相连动力合成器，每格一件材料，输出一个高级转速控制器。图案关于水平、垂直与两条对角线对称：

```text
B P C P B
P W E W P
C E R E C
P W E W P
B P C P B
```

- B：黄铜机壳 ×4，结构外框。
- P：精密构件 ×8，精密装配成本。
- C：坚固板 ×4，要求黑曜石粉末、熔岩加工和压制配套。
- W：AE 工程处理器 ×4，精密控制部件。
- E：Mekanism 强化合金 ×4，冶金与化学加工配套。
- R：原版转速控制器 ×1，中心。

材料来自当前 Create、AE2 与 Mekanism。成本覆盖流体、精密装配、处理器和合金加工生产，与 ME 路线共享基础工业链；不添加模组。坚固板属于矿物与流体工业加工，精密构件属于装配产品，本次不新增资源路线或维度职责。材料与成品接入现有跨维度物流即可集中供应。

## 行为

注册在现有 RPM Limit 模组：`dimensionworks_rpm_limit:advanced_speed_controller`。继承 Create 的转速控制器方块与方块实体，直接引用其模型、贴图和渲染器，保留放置、扳手、应力和转速转换逻辑。补充原版转速传播对新方块的识别，保留大齿轮位置与轴向约束。

隐藏原滚动数值框。右键显示自绘黄铜边框、灰色铸件与深绿读数面板；输入整数后回车或 Esc 关闭即提交。负数反转，0 停止。非法或越界输入保留旧值。目标范围取 RPM Limit 与 Create 上限较小者，当前默认 ±10,240 RPM；实际转速仍受所有者的齿轮之心限制，第一项修复后默认仍为 512 RPM。

使用原版目标值 NBT、同步和更新回调。服务端检查菜单、方块、距离、建造权限、已加载区块及数值范围，保留既有所有者，缺少所有者才记录编辑玩家。

## 性能与验收

每个方块一个继承自 Create 的方块实体，没有新增实体、区块强加载、跨维度常驻任务或每 tick 扫描。仅在目标值变化时通过原版回调刷新动力网络。动力合成器阵列可回收或复用。

构建与静态检查不等于游戏验证。需在游戏中验收正反转、零转速、上下游供能、齿轮朝向、重载持久化、Flywheel 与普通渲染、多人编辑以及齿轮之心限速。

## 0.4.10 崩溃修复

服务器 2026-10-30 的崩溃报告显示 `StackOverflowError`，栈反复进入 `RotationPropagator.propagateNewSource:261`。控制器目标值超出接收方转速额度时，传播器预测值大于 `setSpeed` 限幅后保存的转速，触发无限的“较快邻居覆盖当前来源”递归。修复将相同的限幅规则前移到传播预测返回边界，保留原版图遍历、来源选择和控制器变速计算，不吞异常，也不删除现场方块。

修复覆盖高级与原版控制器，以及普通齿轮的超限传播。每次传播预测只增加一次现有限幅查询；不增加每 tick 全网扫描或区块加载。

回归结果：在独立 Forge 1.20.1 / Create 6.0.8 开发服务端，未修复代码在同一六场景测试中复现了 `propagateNewSource:261` 的栈溢出；加入修复后六项全部通过。测试不使用生产服世界，不验证生产服全部附属 Mixin 的组合，也不覆盖客户端界面与渲染。

| 场景 | 目标 RPM | 接收方额度 | 实测输出 RPM |
| --- | ---: | ---: | ---: |
| 高级控制器，大齿轮输入 | 1024 | 512 | 512 |
| 高级控制器，大齿轮输入、反转 | -1024 | 512 | -512 |
| 高级控制器，传动轴输入 | 1024 | 512 | 512 |
| 高级控制器，上限内调速 | 128 | 512 | 128 |
| 高级控制器，零目标 | 0 | 512 | 0 |
| 原版控制器，超限目标 | 256 | 32 | 32 |
