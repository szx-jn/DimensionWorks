# 暮色工业彩蛋：弹力打包工具

日期：2026-11-14。状态：用户已确定本页玩法范围；尚未选择暮色合成材料、编写配方或实现运行行为。

本轮彩蛋**只保留弹跳封带**。弹跳封带与现有打包工具合成，产出**弹力打包工具**；由弹力打包工具打包的玩家成为**弹力包裹**。弹跳封带是合成材料，不再按上一版的可拆附件设计。

弹力牵引绳、挂号封签、伪装印章、雪球包装纸、留影胶片均撤回。上一版弹跳封带的跳跃键蓄力、碰壁反弹、可拆附件结构和示例总成不继续采用。

## 1. 工具与合成

| 项目 | 已确定要求 |
| --- | --- |
| 合成关系 | 弹跳封带 + 现有打包工具 → 弹力打包工具；准确配方及其他材料待定 |
| 工具建模 | 与现有打包工具相同，不改变模型 |
| 工具品质 | 提升为绿色品质 |
| 弹跳封带材料 | 使用暮色森林中与弹力有关的材料；先列全物品，再选择具体材料 |
| 适用对象 | 只有玩家可以被打包成弹力包裹；其他对象按原打包工具规则处理 |

当前先提供 [暮色森林全部注册物品](twilight-item-registry-inventory.md) 和 [完整 CSV](twilight-item-registry-inventory.csv)。此清单不等于材料候选已确定，也不承诺其中每项均可在生存模式获取。

## 2. 弹力包裹外观与基础性质

- 弹力包裹整体使用史莱姆色系，稍微调整不透明度；具体色值与不透明度尚未指定。
- 继承原玩家包裹的所有性质，只增加本页明确要求的弹力外观、落地弹跳和蓄力发射。
- 普通打包工具与普通包裹保持原有行为；弹力打包工具不把生物或其他对象变成弹力包裹。
- 用户未指定的工具交互、玩家打包与解包、挣脱、运输、包裹属性以及其他行为禁止改动。

## 3. 落地弹跳

弹力包裹落到地面时，效果相当于玩家踩在史莱姆块上，按对应的原版机制弹起。实现时应核对 Minecraft 1.20.1 的史莱姆块落地与抑制反弹等机制，不能自行另设一套地面反弹规则。

本页未增加墙面反弹，也未指定额外的伤害、速度、摩擦或碰撞改动。落地弹跳与 Shift 蓄力的衔接应同时满足用户指定的操作与史莱姆机制，不能以实现衔接为由改变其余包裹行为。

## 4. 平地蓄力与发射

| 项目 | 已确定要求 |
| --- | --- |
| 触发状态 | 玩家处于弹力包裹状态，在平地上 |
| 蓄力输入 | 长按 Shift |
| 蓄力时长 | 3 秒蓄力满 |
| 强度变化 | 蓄力越多，弹跳与发射力度越强 |
| 释放输入 | 松开 Shift |
| 发射方向 | 玩家当时的视角方向 |
| 发射力度 | 使用当前蓄力对应的力度 |

尚未指定三段各自的力度数值、力度增长曲线、最小或最大速度，以及“平地”的实现判定。这些数值与判定留到实现细化，不把自行估计写成已确认规则。

## 5. 蓄力界面

- 屏幕中下方居中显示，位于物品栏上方 **20 px**。
- 蓄力显示分为**三段**，颜色从绿色到红色，依次代表更大强度。
- **满蓄力变成金色**，满蓄力时间为 **3 秒**。

三段分界、具体色值、显示尺寸和非蓄力状态的显示方式尚未指定。不得借此改动现有物品栏或其他界面。

## 6. 制造方向与当前工作顺序

沿用用户要求的复杂制作和暮色地区成果关联方向，但材料、地区归属、功能部件及加工顺序均未定稿。上一版约 30～40 次加工动作和 32 步例子不再作为本方案的既定要求。

先完成固定版本暮色全物品盘点，再筛选能解释弹力性质的原生材料，最后结合已确定的地区工业部件设计弹跳封带工艺。不能为了复杂而填入无用途材料、重复步骤或等待时间；合成后得到的工具按本页范围直接使用。

这项彩蛋保持可选定位。主地区机械、高级材料工业与维度终端升级继续见 [机械成果](twilight-machine-products.md) 和 [全套规划](twilight-full-production-plan.md)，不由本页另行改动。

## 7. 实现与验证边界

本次只修改设计文档与物品清单，不修改工具代码、配方、模型、材质、品质、HUD、物理行为或 Mod 清单，也未进行游戏内验证。

后续实现先查看现有玩家包裹和打包工具的实际代码及 [玩家包裹与发运规格](../gameplay/parcel-dimension-dispatch.md)。配方优先使用 KubeJS；确需修改 Create-Mobile-Packages 时遵循既有 fork 和固定 Release 流程。

性能增量仅围绕已打包的在线玩家处理运动、蓄力和必要同步，复用现有玩家与包裹表示；不为本功能新增强制区块加载、区域实体扫描或常驻替身实体。新增专属物品统一收录于既有 `dimensionworks_cave_factory:main` 页签。

验证重点是玩家与非玩家的适用边界、史莱姆落地机制、平地 Shift 蓄力、3 秒满蓄力、视角发射和 HUD 位置，以及原打包、解包、挣脱和运输行为的回归。实际验证结果应在实现后另行记录。
