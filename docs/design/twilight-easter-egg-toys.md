# 暮色工业彩蛋：弹力打包工具

日期：2026-11-14。状态：弹跳封带、弹力打包工具及玩家弹力包裹已实现；本地验证见 [验证记录](../validation/2026-11-14-elastic-packager.md)。各地区最终机械及其部件归属仍未定稿，不由本彩蛋另行确认。

彩蛋只保留**弹跳封带**。封带与现有打包工具合成，得到**弹力打包工具**；该工具打包玩家后，玩家成为**弹力包裹**。弹力牵引绳、挂号封签、伪装印章、雪球包装纸、留影胶片继续撤回，封带不采用可拆附件结构，也不增加碰壁反弹。

## 1. 工具与适用范围

| 项目 | 实现 |
| --- | --- |
| 成品工具 | `dimensionworks_transfer:elastic_packager`，名称“弹力打包工具” |
| 合成 | 现有 `create_mobile_packages:mobile_packager` + `kubejs:bounce_tape`，无序合成 |
| 模型 | 直接继承原打包工具的物品模型，几何和材质不改动 |
| 品质 | Forge 绿色品质，工具名称显示绿色 |
| 工具数据 | 升级复制原工具完整保存数据，包括自定义名称、附魔、NBT 和保存的 ForgeCaps；预览不修改原工具 |
| 弹力对象 | 仅玩家；生物与其他对象沿用原打包工具处理 |
| 创造模式 | 专属物品由已有 `dimensionworks_cave_factory:main` 页签按命名空间统一收录，不建立新页签 |

工具继承固定版 CMP fork 的打包工具。物品、方块、生物、菜单与载荷处理继续由原工具执行；玩家免疫、打包尺寸、移速、挣脱、解包、输送与发运继续使用原入口。双手持有不同工具时，直接玩家交互以实际使用的工具决定包裹种类；原有自打包/网络入口沿用原先主手优先规则。

## 2. 弹力包裹外观

包裹仍使用原有玩家实体、包裹模型、朝向和移动表现。仅将玩家弹力包裹转为史莱姆色系，渲染不透明度约 **88%**；工具自身的模型与贴图不改动。普通包裹和生物包裹不使用该配色。

## 3. 落地弹跳

弹力包裹在地面发生向下碰撞时，调用 Minecraft 1.20.1 **原版史莱姆块**的 `updateEntityAfterFallOn`，保留原版对落地速度和潜行抑制反弹的处理。水平速度不另行放大；不新增墙面反弹、地面摩擦规则或伤害改动。

原玩家包裹已有摔落保护和受攻击解包等性质继续保留。正常潜行落地会抑制反弹，站稳后可以按下述方式蓄力。

## 4. 平地蓄力与发射

- 在弹力包裹状态下，站在地面长按 **Shift** 蓄力；空中、实际骑乘和锁链悬挂状态不积累蓄力。
- **60 tick（正常 20 TPS 下 3 秒）**蓄力满；离地清除本次蓄力，持续按住后重新落地从零开始。
- 松开 Shift 后，由服务端按当前蓄力向玩家当时的**视角方向**发射，包括俯仰角。
- 实现采用线性力度：有蓄力时速度为 `0.35 + 3.3625 × 蓄力tick / 60` 格/tick，满蓄力 **3.7125 格/tick**，为原先 1.65 格/tick 的 **2.25 倍**。服务端限制蓄力上限，重复松键不重复发射；未改动原包裹移速倍率。
- 解包、下线、维度切换等状态边界清理运行中的蓄力。打开界面、暂停或处于原有维度钥匙引导锁定时取消蓄力，不将界面操作当作发射。

## 5. 蓄力界面

界面仅在蓄力时显示：屏幕中下方居中，**整个蓄力条底边距离物品栏上边 20 个 HUD 像素**。三个等长段分别呈绿色、橙色、红色，每段对应 20 tick，依次表示更大强度；满蓄力三段全部变为**金色**。不改动原物品栏或其他界面。

## 6. 暮色供料与制造

[完整暮色物品清单](twilight-item-registry-inventory.md) 已先行完成。固定 JAR 中，黏液甲虫和迷宫史莱姆掉落的黏液球是原版 `minecraft:slime_ball`，没有独立的“暮色黏液球”物品。本配方不限制黏液球来源，而以实际暮色材料和已有铁木弹簧赋予支线制造价值。

| 分支 | 工艺与职责 |
| --- | --- |
| 弹性胶料 | 4 个黏液球 + 1 份火焰血 + 250 mB 蜂蜜，经加热搅拌产出 2 份 `kubejs:elastic_compound`。火焰血作为暮色魔法胶料的工艺材料，不宣称改变原物品效果。 |
| 钢叶带坯 | 1 个钢叶锭经切割产出 2 份 `kubejs:steeleaf_seal_strip`，用于封带骨架。 |
| 回弹机构 | 复用 Vintage Improvements 已有大小铁木弹簧、铁木板/杆/线与绕簧配方，不新增弹簧或机器；具体上游路线随已加载的模组兼容条件生效。 |
| 缓冲与封装 | 极地毛皮作为缓冲层，蜂蜜作为层间黏合材料，钢叶锭作为扣件。 |

以一份弹性胶料开始十步顺序装配：

1. 装钢叶带坯。
2. 冲压骨架与胶料。
3. 装大铁木弹簧。
4. 装小铁木弹簧。
5. 装极地毛皮内衬。
6. 注入 100 mB 蜂蜜。
7. 压合内衬。
8. 装钢叶扣件。
9. 压合封口。
10. 切割成品，产出 1 个弹跳封带。

中间状态只使用 `kubejs:incomplete_bounce_tape` 和 Create 的顺序装配进度，不为每步新增零件。最后与旧工具合成；未完成的封带不能用于升级。复杂度来自胶料、带坯、两种弹簧与装配汇合，不使用随机失败、巨量堆料或强制等待。

配方位于 [服务端脚本](../../kubejs/server_scripts/elastic_packager.js)，工件注册位于 [启动脚本](../../kubejs/startup_scripts/elastic_packager.js)。本功能新增四个配方，不删除或替换原打包工具配方。

## 7. 实现、性能与验证边界

运行行为位于现有 `dimensionworks-transfer` 模块，使用整合包已固定的 CMP `0.6.1-dimensionworks.15` 公共类和局部 Mixin 接入；没有修改第三方源码，也没有新增 Mod。

运动与蓄力只处理在线玩家。客户端预测蓄力显示，服务端计算实际发射；按键包只在状态变化时发送，弹力外观状态仅同步给追踪者和本人。不新增替身实体、区块加载票据或区域生物扫描。客户端沿用原包裹渲染，仅弹力玩家使用配色与透明度处理。

已执行的单元、专用服务器和独立客户端检查，以及未穷举的多人/全包场景，均见 [验证记录](../validation/2026-11-14-elastic-packager.md)。本地开发 JAR 用于验证，本次未正式发布整合包或更新现有实例。
