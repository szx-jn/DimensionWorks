# 暮色工业彩蛋小玩具

日期：2026-11-14。状态：玩法与制造结构草案，尚未确认或实现。用户要求增加能帮助游玩、类似现有打包工具魔改的彩蛋，制作尽量复杂，并贴近暮色三个地区的最终成果。

主线仍以 [机械成果](twilight-machine-products.md) 与高级工业能力为目标。小玩具属于可选收藏、出行和多人互动成果，不成为终端升级、机械制造或七个修复碎片的前置。此轮只设计玩法和总成依赖，不编写配方或运行代码。

## 1. 三个地区与首批六件

三个地区沿用 [全套规划](twilight-full-production-plan.md) 的沼泽—火焰沼泽、黑暗森林—高塔、积雪森林—冰川。**各区最终机械及其部件尚未定稿**；以下按地区主题提出玩具，后续须接入真正确定的机械部件，不把旧材料草案或四台待审机械的地区归属写成既定事实。

| 地区 | 玩具暂名 | 玩家直接得到的玩法 | 对应地区成果的挂接方向 |
| --- | --- | --- | --- |
| 沼泽—火焰沼泽 | **弹跳封带** | 包裹压缩蓄力、碰壁反弹；建设弹跳通道和包裹跑酷 | 复用动力机械的回弹、限位、触发部件；若爆压引擎保留，可共享其中的运动机构部件 |
| 沼泽—火焰沼泽 | **弹力牵引绳** | 玩家接上绳端，形成弹性连接；互相牵引、结伴跨越或荡绳 | 复用弹性机构、复合绳材与可解除扣件 |
| 黑暗森林—高塔 | **挂号封签** | 给自己写目的地，沿已有包裹链路前往指定蛙港，到站自动下链拆包 | 复用该区最终机械的识别、执行与读写部件，接高级电路供应 |
| 黑暗森林—高塔 | **伪装印章** | 采样普通方块的外观，把自己伪装成可移动的小道具 | 复用识别样本、切换机构和封装部件；用于捉迷藏、惊喜包裹和工厂活动 |
| 积雪森林—冰川 | **雪球包装纸** | 玩家包裹成为可滚动、可轻推的雪球，玩冰壶或滑行接力 | 复用结晶定形部件、惯性机构与制动扣件 |
| 积雪森林—冰川 | **留影胶片** | 录下一段自己的移动与动作，再播放路径留影给队友看 | 复用精制晶体构件、记录介质与定位部件；用于迷宫带路、路线演示和纪念 |

每区两件是本轮候选结构，不是必须实现的数量。缺少独立玩法或实际用途的候选直接撤回，不用数值强化填满目录。流量计和温度探头继续撤回，冰川的晶体/记录主题不代表新增温控设备。

## 2. 使用体验

### 弹跳封带：把自己变成弹跳包裹

作为现有打包工具的可拆附件使用。玩家打包后，按住跳跃让包裹外形压缩，松开释放一次可控制方向的弹跳；移动中撞到墙面可改变方向并反弹。潜行抑制反弹，方便停靠。

主要玩法是包裹与地面、墙面之间的弹性互动。工厂可以建斜面和转角反弹通道，队友也可以组织包裹跑酷。普通行走速度和最大动力额度不是奖励点。

已有 Alex's Caves 反弹靴提供落地反弹，Supplementaries 有弹射装置，Create 有弹射和运输设施。因此本候选必须真正交付**玩家主动压缩与墙面反弹**，只提高跳跃高度或把落地反弹换成纸箱外观时撤回。反弹不累积无限速度；具体控制和碰撞效果需原型验证。

### 弹力牵引绳：两个人之间的弹性连接

双方各接一个绳端，距离拉开时绳子产生张力，玩家的移动能影响另一端；也可把一端接在适用的固定锚点上，进行荡绳或蹦极。任一参与者可以主动松开。

用途包括两人结伴过沟、帮队友回到平台、多人弹跳挑战。它是连接两个实际端点的弹性约束，不提供跟随 AI、远程传送或额外实体乘客。普通绳梯、牵引生物和背负乘客不能据此被宣称失去用途。

原型先限制为一根绳的两个端点，明确绳长、松弛、张力和断开条件。不能以大规模玩家串联的物理模拟作为交付前提；已有模组若能完整提供同样的玩家弹性连接，则复用现有工具。

### 挂号封签：给自己写一张快递单

用封签读取一个已有蛙港的站名/目标，装到打包工具上。玩家打包后，包裹外显示目的地；进入已有链式包裹路线，到目标蛙港时自动下链并拆包。队友也可把写好目的地的封签交给来访者，作为工厂参观的车票。

新增职责是**玩家包裹的目的地与到站行为**。当前已有上链、骑链和在打包机拆包能力，继续沿用；普通物品的地址编辑和机器人配送已经存在，不重新制造同样的物品快递工具。

首次范围只选择同维度、已连接且可达的蛙港路线。不能预先承诺所有快递员、库存接口或跨维通路都能运输活玩家，不把玩家变成真实库存物品。不搜遍世界寻找地址，不自动建路或强加载远端。骑乘中主动离开、目的地拆除和路线变化的行为须在原型中说明。

### 伪装印章：会走路的南瓜或原木

玩家用印章采样普通完整方块外观，如南瓜、原木、石砖；打包后以该道具外观显示自己，仍是实际玩家，可以观察和移动。解包恢复正常外观。

玩家可以在工厂玩道具捉迷藏、伪装成一份奇怪货物进入参观路线，或用同一类方块外观组织队伍。候选的职责是**实际玩家的可切换道具外观**，不承诺怪物失去索敌或玩家无敌。

采样只保存允许的方块外观状态，不复制容器内容、方块实体或玩家身份。场景里不放置真的替身方块，碰撞和交互继续基于实际玩家。已有纸板护甲隐蔽效果与静态全息投影不能直接当作新成果；如果现有工具已可实现同一可移动玩家伪装，则撤回。

### 雪球包装纸：玩家冰壶

作为另一种包裹附件，启用后以雪球外观包住玩家，并提供地面滚动和惯性滑行。队友轻推可以改变雪球运动，玩家可调整方向并主动制动。适合自建冰壶场、滑行接力和多人运输小游戏。

与弹跳封带分别保留明确动作：弹跳封带处理压缩与反弹，雪球包装纸处理地面惯性与制动。不能只把同一套移动效果换颜色形成第二件玩具。冰面可沿用原有摩擦特性，普通地面也应能演示基本滚动玩法，不要求先改变维度或全局天气。

它仍使用原玩家实体，不生成一颗另载玩家的常驻雪球；不提供冰冻生物、冰炸弹、冰霜行者或环境降温能力。具体碰撞、推力和多人同步尚未验证。

### 留影胶片：把带路过程留下来

持胶片开始记录，再次使用停止；播放时，在路线附近显示一段半透明的角色动作留影，包括行走、转向、跳跃、潜行和包裹状态。队友可以看见带路者如何绕过转角、进入通道或搭乘现有路线。

玩法包括给迷宫出口留下演示、向朋友展示工厂参观路线、记录包裹跑酷。记录的是短片段的角色动作与路径，播放不执行攻击、放置、合成或机器交互，不制造代替玩家工作的分身。

Alex's Caves 已有支持玩家显示的全息投影仪，单纯显示玩家模型不能成为新玩具。这里必须交付**带时间顺序的路径和动作回放**；可复用已有渲染能力时优先复用，不能再加一台静态投影方块。Xaero 地图与路标继续承担地图导航，胶片不自动寻路或保证旧路线仍可通行。

记录只含播放必需的少量轨迹、姿态与外观引用，不保存世界区块或完整背包；展示的装备不成为真实物品。先以一段短录像证明价值，时长、采样和同时播放数量依据客户端成本确定。

## 3. 制作复杂度：多个总成汇合

**制造尽量复杂，使用保持直接。** 将复杂度放在地区部件供给、不同工艺的总成、可回用工具与最终装配。玩具制成后长期复用；不为维持制作难度增加每次使用都要跑完整产线的耗材、定时故障或强制磨损。

建议单件先按以下结构展开：共用精密封装座、四个有独立用途的功能总成、最后的多步汇合装配。每个总成采用多道有实际变化的加工，暂以合计约 **30～40 次有效加工动作**作为复杂制造草案的目标；这是未来配方设计目标，不是已经存在的配方数量或固定游玩时长。

| 玩具 | 四个功能总成的建议职责 | 最后汇合时解决的问题 |
| --- | --- | --- |
| 弹跳封带 | 回弹芯、限位扣、耐热衬带、触发片 | 回弹机构与限位/触发件匹配，再封装成可拆附件 |
| 弹力牵引绳 | 复合绳芯、回弹卷簧、锚扣、解除扣 | 绳材、弹性机构与两端扣件汇合 |
| 挂号封签 | 寻址芯、读写触点、封签基带、回执扣 | 地址介质与读写/到站部件装配，制成空白封签 |
| 伪装印章 | 空白样本片、印章头、切换机构、封带接口 | 样本载体与外观切换机构装配，制成待采样印章 |
| 雪球包装纸 | 晶体外壳、惯性环、制动扣、柔性内衬 | 外壳与控制件汇合，保持可解包的柔性接口 |
| 留影胶片 | 记录片、光学片、走片机构、定位芯 | 记录介质、读出和定位部件汇合，制成空白胶片 |

上述名称表达部件职责，尚不是注册 ID。主地区至少承担体现玩具核心动作的总成；跨区部件只在确有用途时加入，例如高塔触发/读写部件供热区附件，冰川记录介质供高塔样本片。不能每件都机械地塞入三份地区材料。

### 一件弹跳封带的制造展开示例

下表展示约 32 次加工动作如何来自实际部件制造。它是工艺规格草案，具体材料、机器支持与顺序配方尚需核对；不是已经可以放入 KubeJS 的配方。

| 部分 | 加工展开 | 动作数 |
| --- | --- | ---: |
| 共用封装座 | 切割框料 → 压板 → 装衬套 → 注树脂 → 装机械接口 → 压合 | 6 |
| 回弹芯 | 制杆 → 绕簧 → 装轴套 → 装限位环 → 装导向套 → 压合 | 6 |
| 限位扣 | 裁坯 → 成形 → 装销 → 铆合 | 4 |
| 耐热衬带 | 清洗纤维 → 树脂复合 → 压片 → 裁切 → 装边条 | 5 |
| 触发片 | 压印基片 → 接导线 → 装触点 → 封装 → 装扣座 | 5 |
| 汇合装配 | 安装回弹芯 → 安装限位扣 → 安装衬带 → 安装触发片 → 压合外盖 → 完成可拆封装 | 6 |

玩家可以并行生产总成、共用冲压与装配设施、用 AE2 按需调度，或先批量制备标准部件再汇合。不给唯一摆放图；不要求为了一个彩蛋建六种重复机器。最终生产先得到空白附件，玩家写地址、采样外观或记录录像在制成后进行，不把实时玩家数据当成流水线供料。

沿用已有 Create 冲压、切割、注液、机械手和顺序装配；适用时复用 Vintage Improvements 等现有部件加工。固定 JAR 中存在以 Twilight Forest 为条件的铁木/骑士金属绕簧配方，可作为共用部件线索；仍须确认实际注册、标签、上游和完整包配方，不能仅凭语言条目假定炽铁或其他兼容材料都能生产。

副产物和回用只在确有物料依据时设计。中间状态优先沿用未完成工件/顺序装配记录；需要独立储运、供多件玩具共用的总成才注册成物品。不能为 32 次动作注册 32 个只换名字的零件，也不用重复冲压、随机失败、巨量材料或漫长等待凑难度。

## 4. 与已有玩法和主线的连接

- 安装附件扩展现有打包工具，保留原工具数据与基础交互。制造附件不直接吞掉玩家已有工具及其中数据；具体装卸接入按现有接口选择。
- 包裹身体模式一次启用一种：弹跳、伪装或雪球。挂号是目的地设置，可与兼容外观模式配合；牵引绳和胶片是独立手持玩具。切换不靠叠加速度或伤害倍率。
- 上链时沿用现有骑乘处理，解包、发运和挣脱沿用同一入口。玩具模式不拦截主动挣脱，也不替代中转领地终端或打开未解锁维度。
- 制造接地区最终机械的标准部件，扩展同一批产线的订单。是否共享哪个部件等主机械职责确认后决定，不消耗整台无关机器来表现昂贵。
- 这些是可选玩家体验成果，不分配七个碎片能力，不给首领增加干扰设备。不能以玩具为由收回已获得的主世界机制。

## 5. 实现边界、性能与验证

本轮不新增 Mod、不修改 manifest、不修改第三方源码。普通加工配方后续放 KubeJS/数据；玩家运动、包裹状态、目的地和回放需在现有自研模块接口允许的范围内开发。若确需改 CMP，则按仓库要求通过已有 fork 与固定 Release，不能直接改第三方来源。

- 弹跳、滑行和牵引只处理当前启用玩具的在线玩家及其局部碰撞/两个端点，服务端控制实际位移；不扫描区域生物或生成替身实体。
- 挂号复用现有附近蛙港与骑链处理，验证目标变化和到站行为；不添加全球地址扫描或强加载。
- 伪装只同步外观状态，不复制世界方块；普通方块采样先限定到可可靠渲染的类型。
- 留影采用有界短轨迹，只在附近按需播放；不运行实体 AI，不保存区块，不每刻广播整段录像。性能预算依据真实客户端和多人播放结果确定。
- 全部玩具在解包、维度切换、下线、死亡及设备解除等实际状态边界清理运行效果，保留应保存的附件与胶片数据。不补算离线运动，也不把离线玩家装入库存。
- 原型先验证每件候选新增的动作以及现有工具能否完整替代，再验证原打包/解包、输送、发运和多人同步。制造步骤确定后检查真实生效配方、工具回用、顺序装配与代替路线；不能把源码阅读或静态检查称为游玩验证。
- 新增专属玩具和附件统一进入既有 `dimensionworks_cave_factory:main` 页签，不新建彩蛋页签。
