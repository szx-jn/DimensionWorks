# 游戏根目录 VERSION 的唯一版本依据

客户端更新器、服务端更新器和 Forge 登录版本检测统一只读取实际游戏根目录的 `VERSION`。当前安装版本不从 `state.tsv`、更新清单、`modrinth.index.json`、启动器版本名、模组版本、JAR 内资源、工作目录或父目录推断，也不缓存读取结果。

## 文件与目录约定

- 客户端由 `Minecraft.gameDirectory` 确定游戏根目录；检测界面启动更新器时使用同一个目录。服务端使用 Forge 启动时的游戏根目录。更新器只使用自身所在的实例根目录。
- 版本文件固定为根目录下的 `VERSION` 普通文件，最大 64 字节，编码为 UTF-8；允许文件开头的 UTF-8 BOM、首尾空格/制表符和 LF/CRLF 换行。路径按各平台文件系统的原生规则处理。
- 内容为 `x.x.x` 三段非负整数，不允许 `v` 前缀、前导零、后缀或多行版本；每段最大为 Java 有符号整数上限。两端执行相同的解析和数值比较规则。
- 缺失、不可读、非普通文件、错误编码、超限或非法内容均明确报告错误，并记录实际读取路径。禁止把读取失败转换为 `0.0.0`；只有文件明确写入 `0.0.0` 时，它才是实际版本。

## 更新器

先恢复未完成的文件事务，再读取根目录 `VERSION`，随后查询目标发行版。显示当前版本、拒绝降级、选择增量基线及更新结果均使用本次读取的值。签名状态只提供受管理文件及其旧摘要，用于备份、文件筛选与删除保护，其版本字段不参与当前版本判断。

文件不可读或非法时中止更新，不使用完整包、清单或签名状态猜测当前版本。应用前重新读取 `VERSION`，若与本次计划的版本不同则中止。新版本 `VERSION` 与文件状态在同一可回滚事务内更新，并将 `VERSION` 放在事务最后；下载、校验或文件应用失败时不得留下新版本标记。完成后从根目录重新读取并报告版本。

## 登录检测

服务端发送从自身根目录 `VERSION` 读取的版本。客户端在登录握手处理时读取实际游戏根目录 `VERSION`，按数值比较；同版本和更新的客户端允许继续，旧版本显示更新入口。文件读取失败与版本过低使用不同提示；服务端版本非法时关闭更新入口，避免启动无法确定目标的更新。

读取和日志只在登录或单次更新时发生，不新增区块加载、实体、机器或常驻轮询。回归验证覆盖目录含中文和空格、不同工作目录、BOM/CRLF、失败不伪造版本、清单/签名状态与 VERSION 冲突、同版本/新旧版本、文件事务失败与版本标记回滚。自动化验证不代替 Minecraft 实际联机验证。
