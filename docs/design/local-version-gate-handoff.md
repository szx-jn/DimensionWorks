# 本地更新器与游戏关闭交接

版本检查在 Forge 登录握手阶段仅比较客户端与服务端实际游戏根目录的 `VERSION`，文件规则与失败处理见 [`root-version-authority.md`](root-version-authority.md)。客户端统一使用 `Minecraft.gameDirectory`，版本文件读取和更新器交接共用该目录。玩家点击「立即更新」后，识别操作系统与架构，只在该根目录查找对应的本地客户端更新器：Windows amd64 `.exe`、macOS arm64、Linux amd64。Darwin 必须识别为 macOS。此入口不下载或替换本地更新器。

更新器使用独立可交互终端：Windows PowerShell 新窗口、macOS Terminal、Linux 已安装的终端。命令以游戏目录为工作目录，传入服务端目标 `--release vX.Y.Z`，正确处理空格、引号与 shell 特殊字符。

终端交接程序先写入就绪标记，随后只等待当前 Minecraft JVM 的 PID 退出，再执行本地更新器。等待最长 120 秒，超时保留提示并拒绝更新；不枚举、不杀死启动器或其他 Java 进程。Go 更新器原有的目录确认、更新检查、备份与回滚保持生效。

只有收到终端就绪标记，才在 Minecraft 客户端线程调用正常关闭入口 `Minecraft.stop()`。由原版完成断开连接、世界保存与资源释放，最终正常退出。启动过程位于后台线程，不阻塞渲染；忙碌期间抑制重复启动。找不到更新器、架构不支持、权限不足、终端不可用或启动失败时留在游戏界面并显示原因，不调用关闭入口、不生成本模组导致的崩溃报告。

交接文件写入 `.dimensionworks-update/handoff`，就绪标记领取后删除，Unix 交接脚本启动后自行删除。只产生一次短暂交接进程，不新增常驻 Minecraft 线程、区块加载或实体。验证应覆盖平台选择、文件定位、命令转义、失败不退出、重复操作、指定 PID 等待以及独立测试 JVM 正常退出后的交接；模拟脚本不运行真实实例更新。跨平台命令检查与本机测试不等于三平台真实客户端验证。
