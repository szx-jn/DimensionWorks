# 跨维物流与 SU 传输实现与验收

## 当前实现状态

代码已接入以下游戏内容：三级传输端与 GUI、频道配对/权限/持久库存、SU 分配、物品和流体能力、容量升级卡、拆除回收物质球与解包器，以及 AE2 / Mekanism / Create More: Package Couriers 的维度限制。自动化只处理已经加载的传输端，不主动加载区块。当前通过 Java 编译和单元测试；完整整合包启动、维度传输矩阵、长期应力守恒与游戏内 UI 尚未实测，不能据此声称运行时全部验收完成。

主世界、下界、末地组成原版维度组；其他所有维度，包括天境、暮色森林、六个 Alex 洞穴维度和 `dw:transfer`，均按各自的实际维度 ID 处理。

- 同一维度内的自动化物流和网络正常运行。
- 不同维度之间，现有模组的自动化物品、流体、气体及网络连接，仅当两端均属于原版维度组时允许；只要任一端在其他维度，就拒绝建立或继续维持该跨维连接。
- 玩家无线终端是例外：保留终端跨维访问原有功能，不能据此放行连接两个固定网络的设备。无线终端的实际支持范围仍受模组原有条件限制。
- 新增的专用跨维传输设备是例外，可跨任意维度传输 SU、物品和流体；不因此将两个 AE 网格合并，也不自动允许气体传输。
- 玩家旅行和随身物品不受本物流规则约束。暮色森林等维度的专门入口配置独立于自动化维度白名单。

该规则按维度 ID 判断，而不是维度名称、坐标或模组命名空间；同一非原版维度的两处设施仍可互通。管理员命令、无线终端和玩家背包不能被误判为固定设施之间的自动化链路。

## 三级跨维传输设备

玩家放置并绑定一对传输端点，传输 SU、物品和流体。每个端点均是单方块；三级的制造材料和机械合成配方尺寸逐级提高。频道最多两个端点，两端等级不同时吞吐按较低等级计算。服务端保存每个端点的维度、位置和频道所有者，验证加入与管理权限；拆除最后一个端点时先打包库存和升级卡，再释放频道。

| 档次 | 机械合成配方 | 物品上限 | 流体上限 |
| --- | --- | ---: | ---: |
| 一级 | 3×3 | 50 个/秒 | 50 B/秒 |
| 二级 | 6×6 | 150 个/秒 | 150 B/秒 |
| 三级 | 9×9 | 300 个/秒 | 300 B/秒 |

未来配方使用 Create 自动合成器（机械合成器），配方尺寸不是放置后的结构尺寸。初级定位为首次接触跨维物流，材料仅限 Mekanism 和 Create 的工业材料，并应对应玩家此时的工业发展情况；不要求 AE2 材料。中级和高级的材料、升级关系与工业阶段尚未确定。现阶段三个等级均不编写或注册合成配方。

物品和流体分别计额度，可以同时传输；每对设备的两个方向共用对应额度。物品按单个物品计数，不按组数计数。流体按通用单位 1 B（桶）= 1000 mB 计算。秒按游戏刻计为 20 tick，需用整数余数结转处理每 tick 非整数配额；不能在同一 tick 多次调用时重复获得额度。三档应有一眼可辨的纹理与构造细节，不能只改名称；不单靠颜色区分等级。

物品和流体端点使用标准能力接入管道、容器和机器。模拟查询不会扣额度或改库存；插入时按实际接受量结算。库存保存在全服频道数据中，容量减少时保留原有资源并拒绝新插入，直到取出足够内容。洞穴工厂流体不能从通用流体接口绕过安瓿；安瓿按物品传输，稳定时间从进入频道开始，过期后替换为空安瓿和对应来源维度残渣。每件物品与每个物质球的 NBT 大小均有配置上限。

## 实时 SU 传输

沿用 Applied Create ME 齿轮箱现有的实时应力账本思路：输入端是源 Create 应力网络中的真实负载，允许玩家设置应力系数（SU/RPM），输入转速只读取真实有效动力转速，不提供输入转速设定。输入占额按系数乘实际有效转速计算，必须真实计入源网络应力消耗，并参与源网络的过载判定；不是仅记录一个数字。接收端是目标 Create 网络的 SU 动力源，输出转速跟随实际输入转速，提供的容量不得超过源端已实际计费的有效输入。这里的消耗是运行期间占用应力容量，不是每 tick 从库存扣除 SU。设备档次不设固定 SU 传输上限，但不产生 SU、不提供无限源；实现仍受数值类型、现有应力网络限制和有效输入约束。

设备不合并 AE 网格，不使用 AE 存储驱动器，也不绕过现有 Applied Create ME 齿轮箱带宽；它独立读取已加载 Create 动力网络中的实时应力输入并创建目标网络的动力源。输入端系数可调，转速只能读实际动力转速；相同频道内输入转速不一致时停止输出。目标为仅输出已实际扣入源 Create 应力网络的容量，运行时占用应力容量而非从库存逐 tick 扣除 SU。

- 仅当两端有效绑定、端点及其必要的动力网络已加载、源网络供给正常时输出；任何一项失效都停止输出并释放对应占额。
- 输出无缓存、无离线累计、无补发；端点不强制加载区块。重启或重载后先重新校验绑定和实时供给，确认前输出为零。
- 动力变化、过载、拆除、重新绑定和区块卸载时重新结算；禁止残留输出、重复占额和多端重复使用容量。
- 直接 Create 动力网络如果含有本设备的 SU 输出端，则其中的 SU 输入端不再记为新输入，避免直接回灌。跨 AE/FE/其他能量转换器的多跳回路尚未完成游戏内压力测试，是正式宣称应力守恒前的验收项。
- 若目标侧负载超限，遵循 Create 的过载语义；不能因停机、重新连接或重复查询制造免费首刻动力。
- 只处理已登记、已加载的端点及必要网络状态，不做全服方块扫描，不新增常驻实体；多设备时以实际 profiling 确认 tick 成本。

## 现有模组审计与限制

必须在真实连接或传输路径检查两端维度，覆盖已有设施、重启和卸载重载；只删除配方或隐藏物品不足以满足限制。要保留同维度操作、原版三维相互连接及 AE2 无线终端。当前固定版本的静态审计结果：

| 候选机制 | 待核查边界 |
| --- | --- |
| AE2 量子网络桥 | 在 `QuantumCluster.updateStatus` 的网格连接创建点检查两端维度；源码确认此处在尝试重建时先销毁原连接。无线终端不经过此点。Mixin 已实现，待完整启动验证。 |
| Mekanism 量子纠缠传输器 | 频率包含物品、流体、能量、热与化学能力；在频率激活新端点前拒绝不允许的维度，并从被拒端点的 `getFreq()` 隐藏该全局频率。Mixin 已实现，待混合维度频率游戏验证。 |
| Create More: Package Couriers 2.2.1 | 纸飞机的发件维度与目的地维度分别记录；默认允许跨维。`CardboardPlaneManager.addPlane` 创建路线时按同一白名单拒绝目的地，保留原版三维间路线。Mixin 已实现，待运行验证。 |
| Create Mobile Packages 0.6.1-dimensionworks.11 | 固定版本源码显示机器人数据保存于每个 `ServerLevel` 的 `SavedData`，且 `EntityTravelToDimensionEvent` 明确取消 Robo 实体的维度旅行；没有发现全服跨维共享库存。 |
| Create: Additional Logistics 1.4.5 / 其他物流附属 | 当前 jar 的功能集中在包裹地址、加速器、现金登记与列车物流，没有发现可直接跨维传输的固定端点。完整整合包仍需回归。 |
| AE2 Wireless Terminals | 保留原版无线终端行为，属于用户明确要求的例外；不将量子桥白名单扩大到手持终端之外的固定网络连接。 |

审计必须明确物品、流体、气体和网络各自的入口，避免多端共享频率间接连接受限维度。所有相关端点受限后，同一链路不能通过主世界中转绕过；但不能据此禁用玩家手持无线终端。

## 验收矩阵

对每种确认存在的跨维自动化机制，至少验证主世界↔下界、主世界↔末地、下界↔末地允许；主世界↔天境、主世界↔暮色森林、主世界↔各洞穴维度以及两个不同非原版维度间拒绝；同一非原版维度内允许。包含已建立连接后更新、重启、端点卸载重载、多人及权限场景；对多端共享机制验证混合维度频率。SU 另验收零输入、过载、断轴、变速、多个优先级、多端卸载、存档恢复和跨能量转换器回灌。玩家无线终端跨维访问及玩家携带物品跨维单独回归。以上游戏内场景尚未验收。

SU 设备另验收零输入、精确满载、过载、断轴、变速、多个负载、断开与恢复、绑定冲突、权限、两端卸载与重启、多对设备、ME 及多跳回灌，以及长期运行守恒。先做单元和隔离服务器测试，再在完整整合包验证；没有游戏内证据时不得声称已实现严格禁止或守恒。
