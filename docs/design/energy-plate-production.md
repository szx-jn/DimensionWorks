# 能量板工业制造

## 定位

新能量板作为通用工业元件，重新接入原先消耗 Mekanism 能量板的机器、发电机和设备配方。使用普通 KubeJS 物品 `kubejs:energy_plate`，不提供 FE/J 储能或充电能力；旧 `mekanism:energy_tablet` 与储能方块继续退役。

本工艺是常规工业材料生产，不作为齿轮之心修复碎片的能力考核，也不新增进度锁。目标是衔接金属加工、流体供给与机械装配，为持续制造提供可自动化的元件。

## 首版配方

使用 Create 顺序装配，循环一次，固定产出一块能量板，无概率废品。

| 工序 | 投入 | 作用 |
| --- | --- | --- |
| 基底 | 1 个 `create:copper_sheet` 铜板 | 沿用现有金属板加工 |
| 注液 | 250 mB `dimensionworks:molten_gold` 熔融金 | 注液器形成导体层 |
| 装配 | 1 个 `minecraft:redstone` 红石粉 | 机械手安装功能材料 |
| 装配 | 1 个 `mekanism:alloy_infused` 灌注合金 | 机械手安装耦合材料 |
| 定型 | 无额外材料 | 机械压力机完成封装 |

中间物为 `kubejs:incomplete_energy_plate`，由 Create 顺序装配 NBT 记录工序。单块总成本为一块铜板、四分之一个金锭对应的熔融金、一份红石、一份灌注合金。现有熔融配方为一个金锭产出 1,000 mB 熔融金，所以每金锭可供四块能量板使用；这是游戏内的简化制造工艺。

配方 ID 为 `dimensionworks:energy_plate`，数据放在 `kubejs/data/dimensionworks/recipes/`，便于直接调整材料与流体数量。不添加工作台捷径或重复装配循环。

## 下游与绕过边界

- `server_scripts/me_memory.js` 将原生配方中的 `mekanism:energy_tablet` 输入改为 `kubejs:energy_plate`，替代原先统一使用灌注合金的临时方案；其他灌注合金输入保持原样。
- 能量板的新 ID 不在旧储能物品清理列表中。旧能量板的制作、拾取、使用、库存清理和隐藏规则保持有效，不把存量电池兑换成新元件。
- 不恢复能量立方、感应元件等退役物品的输出配方。仍可制造的设备只更换材料，不改变供能机制。
- 铜板、熔融金、红石与灌注合金可由现有产线提供；制造灌注合金的冶金灌注机不依赖能量板，不形成前置循环。
- 核对当前固定版本模组配方与仓库脚本是否存在新元件的其他来源。Create 各阶段必须遵循顺序装配进度，不能把无进度中间物直接压成成品；实际扣料与进度行为仍需游戏验证。

## 物流与性能

成品和中间物是普通物品，可接入现有物品物流与跨维发运；各维度已有资源生产可供料，首版不强制增加维度门槛。熔融金可在装配线附近制备，或使用现有流体物流输送。

加工沿用现有注液器、机械手、压力机和运输设施，不增加自定义逐 tick 扫描、实体生成或强制区块加载。优先在同一工厂区块范围内集中装配，使用传送带或置物台承载物品、保留金液缓冲，并按实际需求运行，减少地面掉落物和闲置机器阵列。

成品和中间物由现有命名空间收录规则进入 `dimensionworks_cave_factory:main`「维度工坊」创造页签，不新增页签。

## 验证边界

本地检查覆盖脚本和 JSON 语法、物品/流体/纹理与翻译引用、完整工序及材料数量、旧储能退役和下游替换。静态检查及模拟注册不能证明 Minecraft 内实际加工成功；发布前应在游戏中检查整线扣料、顺序恢复、JEI、创造页签和代表性下游合成。新增物品需要完整重启。
