# 暮色森林工业支线：资源调查与方案

状态：设计提案，未实现、未在游戏中验证。调查对象为 `manifest/mods.json` 锁定的 Twilight Forest 4.3.2508（CurseForge 文件 5468648；Jar SHA-256 `0bdc89263616d1b35c32ef82c5e9c14cbd20368e2fe8b468c72a28320be7a778`），以及当前仓库脚本、配置和任务。进入方式沿用已有自制模组方案，不在本设计中改动。

## 边界与物品调查

工业与探索仍是两条路线，但允许少量可选交汇：冒险战利品可为工业提供更简便的原料或设备路径；工程师也可建设高复杂度产线生产一次性战斗设备，帮助攻略首领。基础产线与第三碎片不要求首领掉落，进阶工业应有独立替代路线，不授予原版进度或直接跳过保护。具体的工艺层次、战斗装置和互斥依赖见 [暮色共振工业设计](twilight-resonance-industry.md)。

[物品模型全量索引](twilight-item-model-inventory.csv)列出固定 Jar 中 887 个 `assets/twilightforest/models/item/` 模型路径，并关联同名中英文语言键和本包补充中文。它覆盖模型文件而非运行时物品注册表：盔甲纹饰等模型变体、技术方块模型可能不是独立物品；缺模型或名称动态生成的注册物品也可能遗漏。要宣称完整的实际物品列表，仍需启动整合包导出 Forge 物品注册表，与此表比对。模型文件、语言键并不证明生存可获得、可再生或配方已启用。

## 基础工艺：暮色林业—活根冶化—稳定基材

以普通暮色树木及火炬浆果的生态意象，生产独立工业材料 **暮色稳相基材**（暂定名）；它不是暮色原版进度物品。下图是入门阶段，深化后的多支线、循环与功能产物见 [暮色共振工业设计](twilight-resonance-industry.md)。物料流是设计接口而非已经存在的配方：

```text
暮色橡树苗 → 林场 → 原木、树叶、树苗回种
                      ├→ 木质纤维 ─┐
首批火炬浆果样本 → 培育/补种 → 浆果 → 浆果萃取物 ─┼→ 活根培育物 → 活根
外部铁、金、水与动力 ───────────────────────┘        ↓
                        活根 + 粗铁 + 金粒 → 粗铁木 → 铁木锭
                        铁木锭 + 萃取物 + 纤维 → 稳相基材
                                                    ├→ 第三修复碎片
                                                    └→ 工业设备/耗材的后续用途（待设计）
```

1. **供料**：普通暮色橡树苗和浆果样本来自常规森林探索，不要求打 Boss。林场回种并分流原木；植物部分若原生浆果无法自动可持续采收，新增明确的浆果培育配方，至少有净产出，不假定植株自动重生。按普通地貌可达性和保护规则做游戏内检查。
2. **培育**：设计独立的物品或流体中间物，将树木、浆果与水转为可持续活根；首次可以使用自然活根作为样本，但必须明确回收样本且使净产出大于消耗。避免“消耗一活根产一活根”的伪循环；同时核算水、木材、浆果等外部投入，防止无输入复制。具体机器和配比待验证后确定。
3. **冶化**：保留原版 `twilightforest:material/raw_ironwood`（活根 + 粗铁 + 金粒 → 2 粗铁木）与原有熔炼/高炉配方；提供可自动供料的等价工艺仅在原合成无法由现有设备自动化时增加。避免移除原配方或破坏探险玩家制作铁木装备。
4. **稳定加工**：铁木锭与林业、浆果支线的加工物结合，形成专属稳相基材。建议两道不同加工、可缓存物品/流体、无需固定摆放；精确机器、数量、速率与副产物待完整配方审计及试运行确定。若设置副产物，必须有实际可执行的回收或其他用途，不能依靠无限垃圾桶假装闭环。
5. **长期价值**：稳相基材除第三碎片外，建议供后续跨维物流的缓冲/稳定耗材或升级部件使用，具体功能、成本与是否真的消耗另行设计。只供一次性碎片不足以构成长线工业价值；在用途实现之前，它仍只是提案，不能称作已具备持续需求。

设计不强制所有加工必须在暮色进行：林业或样本在其他维度也可能成立。现有跨维政策允许专用传输端搬运物品、流体及 SU，固定的其他模组网络跨到暮色受限；不假定它传气体或自动加载区块。若后续需要证明维度现场生产，须设计可观察的场景约束，不能靠原料名称冒充维度证明，也不强行禁止玩家搬运。

## 第三修复碎片的关联及考核提案

当前 `kubejs/server_scripts/gear_heart_recipes.js` 的第三碎片由精密构件直接富化获得，任务只检查碎片物品；它不要求暮色材料，也不证明工厂运行。提议以稳相基材替换现有直接富化捷径，保留碎片 ID、修复顺序和矿物处理额度 8→64 次/秒的效果。具体配方不在本提案锁定，不能保留旧的廉价配方并声称暮色为必经路径。

- **学习目标**：理解可再生原料供给、两路不同速率物料汇合及中间缓冲的关系。
- **工程目标**：在第三碎片的现有额度之内，让林业/培育、铁木冶化和稳定加工组成可连续运转的跨工序系统；允许玩家自行选择设备及布局。
- **约束**：用可再生样本、真实消耗、可处理的副产物流和受限吞吐构成问题；不能要求先解除第三额度才能生产碎片。维度运输可作为可选工程方案，不要求搬运以证明能力。
- **验收与局限**：建议测试一定周期内稳定供料、成品输出及满仓、断供后的恢复，阈值由实际测量确定。现有 FTB 任务仅持有检查，无法证明这些运行行为；交付一批基材只能证明持有数量，允许手工和交易代工。真正自动验收需要先验证任务系统或另行实现可靠计量机制；不能承诺目前已经能防绕过。
- **迁移**：验收方案应允许不同设备组合，并在试运行中改变一条原料的供给速率，观察玩家如何调整缓存和瓶颈；这目前是人工评审场景，不能声称自动任务能检测。
- **去重**：第一碎片现有方向是组织基本生产流程；第三候选聚焦不同供给速率的协调与恢复，不以操作富化室或 Create 机器本身为考点。当前其他碎片能力尚未全部设计审核，须整体去重后再确定第三项考核分配。

## 实施前必须核实

1. 在锁定版本的完整包内导出注册物品与有效配方、标签和掉落，核对 CSV 漏项及同名模型变体；审查 KubeJS、数据包、其他模组转换、交易、拆解和配方循环。特别检查铁木压块/解压、装备回收、活根和浆果的替代生产，以及新成品是否存在意外来源。
2. 测试暮色树苗的生长、叶片回种、农场机械和浆果采收；检查普通森林样本是否无需任何冒险进度即可获得。固定数量和设备前，测试可达性、原料净收益、物流速率、启动材料与第三额度下的实际能耗/吞吐。
3. 确认专用传输端及其前置材料在第三碎片前可获得；如不可获得，允许暮色内完成或玩家携带物资，不把后续碎片材料设成前置造成循环。
4. 模拟停机、缓冲满载、区块卸载重载与重启；限制常加载区块，仅加载实际生产区，采用有界缓冲和按需启停。优先方块机器和物品管线而非常驻实体农场；魔法树核心的额外 tick、机器数量、掉落物堆积要实测，不承诺固定 TPS。
5. 检查原生 Create、Mekanism、AE2 教学及本包任务与其重复程度，设计可靠考核后再改第三碎片配方与任务。新增专属物品须进入既有 `dimensionworks_cave_factory:main` 页签，并补语言、贴图、JEI 和运行验证。探索主线的原配方、掉落及进度应逐项回归；允许的辅助效果按新设计单独测试。
