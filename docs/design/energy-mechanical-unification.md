# FE 与机械应力统一

## 计量契约

整合包生产与消费的机械功率以 `1 FE/t = 2 SU` 为统一换算。Mekanism 的内部单位是 J，必须读取当前 `EnergyUnit.FORGE_ENERGY.convertFrom(ONE)` 的 J/FE 比率后用除法换算，避免原版四位小数逆数缓存的精度和刷新问题，不能把 J 或最大传输上限当作实际 FE/t。SU 是实时网络容量，不是库存，不补算区块卸载期间的输出。

## 接入范围

- Mekanism 单方块发电机按完整子类服务端更新实际产生的 J 计量，保留原版燃料、环境、红石与热量逻辑；清除旧库存，禁止电缆与能力重复导出。
- 工业涡轮与聚变反应堆在共享多方块数据每次 tick 的边界计量一次，通过已加载的阀门/输出端口连接普通 Create 轴。所有机械端口共享一次发电，不能每端各自复制全部功率。
- MEK 机器按原版当前能耗、工厂并行数及即时配方并行倍率确定额定 J/t，乘机械吞吐倍率后换算 SU。虚拟能源必须有有限预算；模拟不扣除、执行才扣除；预算不能跨 tick、跨机器或存档积累。
- 激光发射器以原版激光每 tick 消耗计费；激光放大器/牵引光束保留原版光束内部储能和脉冲规则，不可从机械动力凭空填满储能。
- AE2 及 ExtendedAE/NeoECOAE 的 `AEBasePoweredBlockEntity` 外部 FE/RF 入口关闭，AE 内部缓冲、网格供能与便携物品充能保留，避免已退役能源接收器之外的备用 FE 输入。
- Applied Create 应力能源接收器通过 AE2 的 FE/AE 换算计量，过载与零转速必须停止向 AE 网注能；保留 AE 自身频道、内部缓冲与耗能机制。
- 龙之进化反应堆总输出按原版 FE/t × 2，在稳定器间分摊；护盾输入也必须按实际注入 FE 计费，不能按固定低应力无限补盾。
- 便携设备是机械充电的终端，不能把便携 FE 库存当作新的机械能源。现有 FE 储能方块的退役规则继续生效。

低速设备先积累足额机械工时，再执行一次原版逻辑更新；局部工时在卸载、重连或变速后丢弃，避免反复重载取得免费首 tick。设备换算额继续受既有 Create 过载、玩家转速和齿轮之心全网配额约束；后期验收使用已修复齿轮之心的独立测试角色。

## 生命周期与性能

所有路径只查询已加载方块。普通发电机只检查相邻六面；多方块只在本体 tick 边界枚举原版已登记阀门，缓存端口快照；不扫描世界、不新增实体或强制加载区块。物理转轴只使用一套来源控制逻辑，防止不同桥接 Mixin 互相移除来源。断开、失效结构、停机、过载与重载后撤销旧输出。

## 验收

数值回归覆盖自定义 J/FE 比率、零发电、非法值、多端口守恒、额定机器负载与有限预算。实际 Forge 客户端在独立世界验证发电停启、燃料/环境、机器加工、外部抽取、过载恢复及重载；明确区分静态检查、Java 测试、客户端实测和未覆盖场景。最终产物由 GitHub Actions 正式发布流程生成。
