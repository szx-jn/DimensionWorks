# Create 遮挡优化独立客户端验证

## 原因与修复

Create 6.0.8 的旋转部件通过方块实体渲染器和 Flywheel 1.0.5 实例分别绘制，整合包的 Embeddium 区块遮挡不能直接阻止这些提交。新增客户端模组 `dimensionworks_create_culling`，不修改第三方源码或机器模拟逻辑。

普通路径在渲染调度器入口跳过；Flywheel 路径在视觉更新完成后、引擎上传前串行设置实例可见性，继续保留更新和光照。完整不透明外壳、两端封闭的机壳轴、覆盖整个投影截面的不透明墙才作为剔除依据。每帧重新判断，预算耗尽时保留绘制。

首次真实测试发现普通轴返回 3×3×3 的默认渲染包围盒，导致实际六面封闭仍保留绘制。改为已核对模型的单方块边界；大小齿轮、风扇和机械泵额外扩大旋转范围，水车保留 Create 提供的完整渲染边界。没有缩减水车范围或忽略齿尖。

## 已运行的独立测试

[验证工作流 41606301901](https://github.com/szx-jn/DimensionWorks/actions/runs/41606301901)，候选提交 `8337e04`，三组全部成功：

| 组合 | 实际客户端断言 | 结果 |
| --- | ---: | --- |
| Forge 47.4.23 / Create 6.0.8 / Flywheel instancing | 259 | PASS |
| 同版本，Flywheel off，普通渲染 | 102 | PASS |
| Flywheel instancing + Embeddium 0.3.31 + Mekalus 1.8.0.1 | 259 | PASS |

三个客户端分别使用新建隔离世界、Xvfb 与 Mesa 软件 OpenGL。测试入口仅存在于 `src/probe`，不进入正式 jar。实际创建九个测试部件：两种封闭轴、被墙挡住的大小水车和齿轮箱、裸露轴、玻璃后的水车、部分遮挡的大水车以及裸露风扇。

验证六个阶段：初始遮挡；关闭优化恢复全部实例；重新启用并重建渲染器；拆墙恢复；移动镜头至墙后恢复水车；更换水车材质、返回墙前后重新剔除新实例。Flywheel 直接检查真实实例句柄可见性；普通路径同时确认实际调度器的跳过计数。三个运行均输出 `PASS COMPLETE`，合计 620 个断言。

10 项 JUnit 几何测试全部通过，包括六向不透明墙、中心开孔、部分遮挡的大边界、反向墙、负坐标、非法范围，以及 300 个随机场景与独立线段/AABB 相交算法对照。随后补充相机位于外壳内部时不得误剔除的回归，正式发布门禁会重新运行完整测试。

已读取兼容组合的六阶段截图，确认关闭优化前后的画面保留玻璃后的水车、裸露部件和大水车边缘，拆墙后被遮挡模型出现，移到墙后水车可见。报告、截图、日志及测试 jar 在该运行的 artifacts 中。

## 发布与边界

正式发布工作流以相同的三组客户端验证作为前置依赖；验证失败不能进入打包。整合包只向客户端安装此模组，服务端排除。另提供独立重混淆 jar 和 SHA256SUMS，检查 jar 不包含运行探针。

本次为真实 Forge 图形客户端与集成服务器测试，不是仅编译或模拟几何测试。未进行完整整合包长时间生产线压测、硬件显卡 FPS 对比或玩家手工验收；不承诺固定帧率提升。光影启用时主动保留绘制，未声称测试了光影阴影效果。移动结构、皮带、机械臂、活塞等动态伸出模型保持原行为。
