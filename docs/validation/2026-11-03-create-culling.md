# Create 遮挡优化独立客户端验证

## 原因与修复

Create 6.0.8 的旋转部件通过方块实体渲染器和 Flywheel 1.0.5 实例分别绘制，Embeddium 区块遮挡不能直接阻止这些提交。新增客户端模组 `dimensionworks_create_culling`，不修改第三方源码或机器模拟逻辑。

普通路径在渲染调度器入口跳过；Flywheel 路径在视觉更新完成后、引擎上传前串行设置实例可见性，保留更新和光照。完整不透明外壳、两端封闭的机壳轴、覆盖整个投影截面的不透明墙才作为剔除依据。每帧重新判断，预算耗尽时保留绘制。

真实测试发现普通轴返回 3×3×3 的默认渲染包围盒，导致实际六面封闭仍保留绘制。改为已核对模型的单方块边界；大小齿轮、风扇和机械泵额外扩大旋转范围，水车保留 Create 提供的完整渲染边界。

整合包默认开启 Complementary 光影，因此使用 Flywheel 的光影兼容 API 区分通道：主视角继续优化，阴影通道保留原有绘制。光影下默认退回普通渲染；第三方强制实例化后端的共享实例保留绘制。没有为了剔除而关闭整合包光影。

[最终独立客户端验证 41608969159](https://github.com/szx-jn/DimensionWorks/actions/runs/41608969159)，候选提交 `5dc0cf6`，四组全部成功，通过后才合入补充修复：

四个客户端分别使用新建隔离世界、Xvfb 与 Mesa 软件 OpenGL。测试入口仅存在于 `src/probe`，不进入正式 jar。实际创建九个测试部件：两种封闭轴、被墙挡住的大小水车和齿轮箱、裸露轴、玻璃后的水车、部分遮挡的大水车以及裸露风扇。

验证六个阶段：初始遮挡；关闭优化恢复全部实例；重新启用并重建渲染器；拆墙恢复；移动镜头至墙后恢复水车；更换水车材质、返回墙前后重新剔除新实例。Flywheel 直接检查真实实例句柄可见性；普通路径确认实际调度器的跳过计数。四个运行均输出 `PASS COMPLETE`，合计 752 个断言。

光影包使用清单固定版本并校验 SHA-1。Complementary 默认关闭方块实体阴影，因此在隔离实例内设 `ENTITY_SHADOW=2`，实际触发阴影通道。探针同时确认光影处于启用状态、主视角发生剔除、阴影渲染确实绕过剔除；不是仅安装光影模组或只检查配置文件。此测试选项不随整合包分发。

11 项 JUnit 几何测试全部通过，包括六向不透明墙、中心开孔、大水车边缘、反向墙、负坐标、非法范围、相机位于外壳内部，以及 300 个随机场景与独立线段/AABB 相交算法对照。

已读取无光影组合的六阶段截图及启用 Complementary 的初始/拆墙截图，确认玻璃后的水车、裸露部件和大水车边缘保留，拆墙后被遮挡模型出现，镜头移动后水车恢复。报告、截图、日志和测试 jar 保存为该运行的 artifacts。

## 发布与边界

正式发布工作流将相同四组客户端验证作为前置依赖，失败不能进入打包。整合包仅向客户端安装此模组，服务端排除。另提供独立重混淆 jar 和 SHA256SUMS，检查 jar 不包含运行探针。Gradle 缓存统一由 setup-gradle 管理。

这是实际 Forge 图形客户端和集成服务器验证。未进行完整整合包长期生产线压测、硬件显卡 FPS 对比或玩家手工验收，不承诺固定帧率提升。移动结构、皮带、机械臂、活塞等动态伸出模型保持原行为。

提交前静态检查：`git diff --check`、工作流 YAML 与嵌入 Bash 语法、清单和模组 JSON/TOML、版本一致性、Python 语法、`pack_hook.check_manifest()` 均通过。仓库 Python 测试 74 项全部通过；本机未编译或打包模组。发布说明生成逻辑以四类样例输入执行，确认每条更新独占一行。
