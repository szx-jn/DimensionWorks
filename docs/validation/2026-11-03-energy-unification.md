# FE 与机械应力统一审查及验证

## 范围与规则

以 `manifest/mods.json` 的固定版本为准，结合能源能力引用、类继承、配置、配方和自研桥接逐项审查。Mekanism 使用 J，统一先除以当前 J/FE 比率，再按 `1 FE/t = 2 SU` 计量。使用正向比率读取，避免原版四位小数逆数缓存的误差与失效问题；源端浮点取整不增加产能，负载取整不减少计费。

| 系统 | 审查与处理 |
|---|---|
| Mekanism 10.4.16.80 加工、工厂、化学机器 | 以原版当前耗能、工厂进程数和即时配方并行计算额定负载；每 tick 有限虚拟预算，模拟不扣、执行扣除，先挂入真实 Create 网络再工作 |
| MEK 特殊设备 | 激光发射器按原版用量计费；放大器保留真实光束缓冲；SPS 补齐机械输入；传送机按原版目的地/实体计算结果申请突发负载 |
| Mekanism: Generators 10.4.16.80 | 普通发电机测量完整子类 tick 的实际产电；工业涡轮、聚变结构共享计量一次；所有原生输出面/阀门轴分摊总量，禁止重复 FE 外送 |
| Applied Create 1.1.5、AE2 15.4.10 | 应力能源接收器按实际 SU ÷2 转 FE，再用 AE2 比率转 AE；过载与断轴停止注入 |
| ExtendedAE 1.20-1.4.14、NeoECOAE 20.4.2 | 确认其机器继承 AE 网供能基类，统一关闭备用 FE/RF 方块输入，保留 AE 网供能和缓冲 |
| Draconic Evolution 3.1.2.621 | 四稳定器共享一次真实 FE/t ×2 输出；护盾与冷启动只使用输入网络可支付的 FE，调用原版 injectEnergy；统一转轴来源控制 |
| Sophisticated 电池、AE/MEK 便携工具 | 保留物品内部充能；机械充电板按有限预算充电，便携电池不成为新的机械动力来源 |
| FTB Quests、Titanium、Balm | 核对 FE 任务/接口与基础库、开发用创作设备；当前任务没有 FE 消费目标，没有发现其他生存工业发电桥接路径 |
| 原生 Create 动力 | 保留其 SU 机制及既有齿轮之心转速、全网应力配额 |

普通发电机只查询相邻六面；多方块只遍历原版已登记阀门并缓存共享端口快照。原始 FE 库存不恢复为应力，区块卸载不补算产电。低转速先积累足额机械工时，卸载、重连或变速不会反复赠送首个工作 tick。

## 本地环境及验证方式

用户明确要求本地启动客户端验证。本次在隔离实例使用 Java 17.0.21、Gradle 8.8、正式 Forge 47.4.23 客户端，以及完整清单内客户端模组；图形由 Xvfb 和 Mesa 软件 OpenGL 提供，验证时关闭光影。正式整合包不在本地打包。

独立探针位于 `mods/dimensionworks-mek-stress/src/energyProbe`，需显式运行 `energyProbeJar reobfEnergyProbeJar`，不进入生产主 JAR。探针建立可丢弃超平坦世界，使用原版设备、配方与世界 tick；后期设备使用已修复齿轮之心的测试角色。正常配额仍生效：较早的测试角色未解除配额时，龙堆只收到全网剩余容量对应的充能，AE 接收器也按过载停止。

完整客户端验证中另发现 LuckPerms 在客户端不初始化而 FTB 权限适配调用其 API，导致单人世界进出崩溃。清单改为服务端专用，服务端继续分发，客户端独立世界正常进入、保存和退出。

## 结果

完整客户端在最后一项产物取整修正之前完成 249 项检查，覆盖 71 种 MEK 设备、发电与多端口、龙堆冷启动及停机、AE 输入、过载恢复和便携充电。两个独立游戏内网络测试通过。最后的低速调度和产物向下取整修正经过 Java 单元测试；用户指定不再追加客户端或存档重载测试。

验证边界：能源注册表覆盖和有限预算检查不等于逐条运行每一个模组配方。聚变用原版已成型结构及热量夹具验证真实热交换发电；常规燃料、安全与故障逻辑继续由上游执行。测试世界、日志、截图和探针 JAR 不进入正式整合包。
