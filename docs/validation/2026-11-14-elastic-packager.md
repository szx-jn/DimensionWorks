# 弹力打包工具本地验证

日期：2026-11-14。实现模块：`dimensionworks-transfer` **0.3.9**；整合包版本记录更新为 **0.3.43**。本次完成代码、资源、配方与本地开发验证，不执行正式发布或更新现有实例。

## 实现范围

- 新工具 `dimensionworks_transfer:elastic_packager` 继承固定 CMP fork 的打包工具，直接继承原模型，使用绿色品质。
- 玩家弹力标记在原打包检查成功后确定；双手工具的直接交互按实际工具处理。普通玩家包裹、生物封装、免疫与五次挣脱继续走原路径。
- 落地调用原版史莱姆块反弹，保留潜行抑制反弹；仅玩家弹力包裹使用约 88% 不透明度的史莱姆色系。
- Shift 地面蓄力由服务端计时并限为 60 tick，松键按当前视角发射；客户端显示三段蓄力条，满蓄力全金色。整个条底边距物品栏上边 20 个 HUD 像素。保留原维度钥匙引导锁定。
- KubeJS 新增胶料、钢叶带坯、十步封带装配与保留数据的工具升级，共四个配方，不删除原配方。专属工具及工件的命名空间符合已有统一创造页签的自动收录条件。

## 编译与单元测试

Java 17 / Gradle 8.8，在 `mods/dimensionworks-transfer` 执行 `test jar`，编译、重混淆和 **23 项 JUnit 测试**通过，失败和错误均为零。其中 5 项新增蓄力测试覆盖连续蓄力上限、重复输入/释放、离地清除、空中不积累和力度增长。

检查生产 JAR 的版本与内容：只包含主源码和资源，不包含 GameTest、客户端测试代码、测试结构或 CMP 第三方类。本地 JAR 仅用于开发验证。

## 专用服务器集成检查

使用 Forge 1.20.1 / 47.4.16、Create 6.0.8、固定 CMP `0.6.1-dimensionworks.15`、暮色 `4.3.2508`、KubeJS 与 Create 附属、Vintage Improvements，以及原 Transfer 测试所用 AE2/Mekanism 等固定 JAR。在仓库忽略的独立测试目录运行，复制本次两份生产脚本，不修改玩家实例脚本或存档。

```sh
gradle -PtransferTestModsDir='<固定版本模组目录>' -PelasticRecipeCheck \
  -PtransferGameTestNamespaces=dimensionworks_elastic,dimensionworks_transfer \
  test jar runGameTestServer --no-daemon
```

**30 项必需 GameTest 全部通过**：10 项新增弹力/配方检查，加上 20 项已有中转、包裹、运输和解包检查。

新增覆盖包括：

1. 原工具与弹力工具只在弹力状态、外观与品质上区分，包裹尺寸、移速和挣脱状态一致。
2. 原免疫拒绝打包，实际副手工具决定种类，五次挣脱仍授予原免疫。
3. 石头落地以史莱姆机制反弹，水平速度不放大；Shift 抑制反弹，解包恢复普通落地。
4. 服务端蓄力封顶，完整俯仰/朝向参与发射，重复松键不重复发射，部分蓄力力度较弱。
5. 离地、解包和原引导锁定阻止蓄力发射，非弹力玩家不能通过输入包取得该能力。
6. 生物仍成为原打包生物物品并放入普通包裹，不带弹力标记。
7. 工具升级保留自定义名称、附魔及完整物品 NBT，预览不修改输入。
8. 实际 KubeJS 升级配方保留旧工具数据，并拒绝未完成封带。
9. 实际 Create 十步装配逐步记录进度，只有最后一步产出成品封带。
10. 胶料、带坯与固定 Vintage Improvements 大小铁木弹簧配方、标签及产物均能解析。

测试只按本次涉及范围验证，不改变原模组配方。最小测试组合中出现了已有 MegaCells 的可选 EMC 掉落条目和 Vintage Improvements `minecraft:blaze_wire` 配方缺项日志，另有 Mekanism 原生水蒸气标签缺项提示；这些条目不属于本次新增配方，也不在弹力制造链中。四个新增配方实际加载成功，相关上游及最终合成已独立断言通过。

## 独立客户端检查

按需运行 `-PelasticClientCheck`，使用 `src/elasticClientTest` 中的测试程序和 `run-elastic-client` 下从 GameTest 世界复制的临时存档；生产 JAR 和常规构建不包含该测试程序。测试客户端使用独立 options 与脚本/资源，未修改已有玩家实例。

```sh
gradle -PtransferTestModsDir='<固定版本模组目录>' \
  -PelasticRecipeCheck -PelasticClientCheck jar runClient --no-daemon
```

客户端实际加载并完成模型、渲染、HUD 和运动检查，输出 `ELASTIC_CLIENT_CHECK_PASS` 后正常保存并退出。检查包括：

- 对比原工具与新工具的实际烘焙模型顶点，几何一致。
- 第三人称实际渲染史莱姆色系包裹，确认背景可透过包裹部分显示。
- 部分蓄力显示三段颜色；检测三段中央实际渲染像素全部为金色后才松开 Shift，避免把未满蓄力截图当作满蓄力证据。
- GUI 为 367×250，界面缩放为 3；蓄力条整体底边按 HUD 坐标距物品栏上边 20 像素。
- 真实客户端收到服务端速度后向指定俯仰方向移动，最后解包状态同步恢复。

截图仅保留于忽略的 `run-elastic-client/screenshots`，不提交仓库。首次检查因窗口失焦自动暂停未完成发射验证；恢复测试后通过，再针对满蓄力金色与最终条边界完成检查。最小组合的原生配方聊天警告曾遮挡 HUD 像素检查，测试程序仅在独立客户端隐藏聊天，确保检测的是蓄力条本身。临时客户端关闭时保存其独立世界，不涉及现有存档。
