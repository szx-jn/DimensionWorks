# 性能约束

首版目标是在同一服务器中支持约 50 台持续加工的洞穴工厂设备和 200 台已组装但多数空闲的设备。

## 结构成本

- 3x3x3 机壳方块必须是普通无 BlockEntity 方块。
- 每台结构只保留一个中心控制器 BlockEntity；最多六个面心端口由控制器驱动，端口不独立 tick。
- 端口能力和状态只在配置、组机状态或内容变化时同步。

## 运行成本

- 维度不匹配、未组机或条件不足时降频检查，只保留最低限度的红石和结构失效检测。
- 配方查询按输入指纹缓存，并在数据包重载时失效。
- 不使用每 tick 全服扫描、实体查找或方块状态写入。
- 效果流体过期采用时间戳懒结算；只在玩家跨维、封装被工厂读取或进入受支持转运路径时检查。

## 验收

## 自增殖链成本

- 自增殖链只用 Create 自有机器与方块，不新增 BlockEntity，也不新增自研 tick 逻辑。
- 不放置区块加载器；产线只在已经加载的区块内运行。
- 不新增实体生成。Sea Pig 工位按每栅 8 只封顶，不扩展为常驻 AI 农场。
- 闲置 Deployer 不持续交互，投喂节奏由传送带与部署器自身控制。
- 不新增后台扫描、全局库存盘点或概率性随机事件；所有结算都由 Create 机器驱动。

- 50 台持续运行设备与 200 台加载设备下，控制器和端口不得产生明显 tick 热点。
- 使用 Spark 或 Forge profiler 检查时，工厂逻辑不得主导区块实体 tick。
- 大规模阵列的应力成本必须随超速并行倍数同比放大，不能在不增加应力的情况下获得超速产能。
