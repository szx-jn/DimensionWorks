# 洞穴六维基础产物自增殖设计

日期：2026-09-27

## 目标

Alex's Caves 六个洞穴维度的基础产物此前只能靠探索搜刮。本设计给 18 类基础产物各补一条可再生循环，使玩家拿到首个环境样本后就能靠 Create 工序建立净增长库存，而不必依赖洞穴工厂签名机。

自增殖属于资源获取层，不属于后期工厂层。它不依赖洞穴工厂、不新增机器、不新增 BlockEntity，也不做后台扫描；所有配方、标签与任务都在 KubeJS 与数据包中完成。

## 核心规则

- 每项产物有“一主一备”：主链模拟维度生态，备链消耗本维残渣回收。
- 主配方不消耗目标产物本身，只消耗可再生母料或普通材料，保证从首次环境样本开始即可净增长。
- 备链统一为 `2 个本维残渣 + 1 个可再生辅料 → 1 个目标物`。
- 残渣只能回收，不能反向制造无限残渣；残渣来源是签名机的故障结算与过期封装。
- 青钕、赤钕、充能方铅岩三色、明胶五色与冰糖十六色共享主链基础产物，再由现有染色、磁化或批量压铸配方区分，避免重复设计。
- Sea Pig 是唯一进入必需主链的实体：每工位最多 8 只，使用 Deployer 投喂 `#alexscaves:sea_pig_digests`。消化产物按原生行为以掉落物形式生成在世界中，收集装置由玩家自行搭建。
- Ferrouslime、Sweetish Fish、Gamma Roach、Vesper 等只进入可选加速方案；断种后通过野外重捕、桶装或原生繁殖恢复。
- 主链验收下限为正常供料下每个维度至少 `8 个目标物/分钟`或 `1000 mB 流体/分钟`，扩建时线性增长。

## 六维矩阵

| 维度 | 主循环 | 保底回收 |
| --- | --- | --- |
| 磁场 | 黏液球 + 铁粒 + 水在 Mixer 生成富铁黏液；富铁黏液 + 废金属 + 红石/青金石反应成粗赤钕与粗青钕；深板岩 + 铁粒 + 燧石压出方铅岩，方铅岩 + 粗钕 + 水生成充能方铅岩。 | 极性残渣 + 废金属/红石分别回收富铁黏液、粗钕和充能方铅岩。 |
| 原始 | 方解石 + 骨粉 + 水压成石灰岩；南洋杉木料在 Mixer 中提取树脂；树脂 + 发光地衣 + 骨粉培育星树果。 | 原生残渣 + 方解石/松子/发光地衣回收三项。 |
| 毒化 | 火药 + 玄武岩 + 酸液生成硫粉；深板岩 + 玄武岩 + 铁粒重整为辐射石，辐射石经 Spout 酸蚀；酸蚀辐射石 + 硫粉在 Crushing Wheels 中提取铀晶碎片。 | 衰变残渣 + 火药/辐射石/酸蚀辐射石回收三项。 |
| 渊海 | 贻贝与淤泥压成贻贝培养，收获后与淤泥、海晶砂压成渊海石；发光地衣 + 海腌菜 + 海晶砂培养生物荧光质；海猪投喂周期按原版消化表产出海雪。 | 渊压残渣 + 淤泥/发光地衣/黏土回收三项。 |
| 异寂 | 骨粉 + 腐肉 + 水生成鸟粪，再与粪岩压成秽岩；荆棘枝条 + 肥料回收树苗，Mixer 将木料循环成原木；黑羊毛 + 暗影丝绸生成暗布，再经 Fan 转为纯粹黑暗。 | 暗相残渣 + 粪岩/骨粉/暗布回收三项。 |
| 糖果 | 糖 + 薄荷粉 + 紫色苏打在 Press 中压成冰糖；干燥海带 + 糖 + 黏液球 + 紫色苏打生成明胶；水 + 糖 + 甜浆果 + 明胶生成紫色苏打。 | 糖晶残渣 + 糖/干燥海带/水回收三项。 |

## 生物使用约束

本设计不新增任何生物。不允许新增 `EntityType`、实体模型、动画、碰撞箱或贴图；所有涉及生物的环节都只使用模组自带生物加机制改动。

改动优先级：

1. 数据层：投喂标签、战利品表、繁殖条件、已有配方的引用，
2. 交互层：用 Create 的 Deployer 投喂、Belt/Chute/Arm 搬运、Funnel 分拣驱动原生行为，
3. 代码层：必要时在自己的模组里对现有生物做机制 mixin，不改第三方源码、不新加渲染资源。

海猪链只用到第 1、2 层：`SeaPigEntity#digestItem` 调用 `Entity#spawnAtLocation` 把消化战利品作为掉落物丢到世界上，因此不需要假玩家背包回收，也不需要改生物本身。玩家自行用 Chute、Belt 或 Arm 做收集。

可选加速方案（Ferrouslime、Sweetish Fish、Gamma Roach、Vesper 等）同样只能以标签、战利品表或原生繁殖方式引用，不得替换为新生物。

## 数据与任务接口

配方全部写在 `kubejs/server_scripts/cave_self_propagation.js`，使用稳定 ID：

- 主链：`dimensionworks_cave_factory:self_propagation/<dimension>/<target>_primary`
- 备链：`dimensionworks_cave_factory:self_propagation/<dimension>/<target>_recovery`
- 中间物：`dimensionworks_cave_factory:self_propagation/support/<dimension>/<name>`

目标组标签位于 `kubejs/data/dimensionworks_cave_factory/tags/items/self_propagation/`，流体目标位于同结构的 `tags/fluids/self_propagation/`，供任务、JEI 说明与后续模块映射引用。

`module_recipe_rule/phase_converter.json` 只映射渊海主链的 `abyssmarine_primary` 与 `bioluminesscence_primary`；其余模块不参与必需循环，也不作为任务门槛。

FTB Quests 单章“洞穴生态工业”包含一个共用前置和六条维度分支，每支包含建设 Create 工序、完成首次增殖、建立残渣回收和交付库存四类节点。任务只负责引导，配方不做硬锁。

## 性能约束

- 不放置区块加载器；产线只在已加载区块运行。
- 不新增实体生成。Sea Pig 工位按每栏 8 只封顶，不扩展为常驻 AI 农场。
- 不使用后台扫描或概率性全局检查；所有结算由 Create 机器本身驱动。
- 闲置 Deployer 不持续交互；投喂节奏由 Create 的部署器与传送带控制。

## 验收

- 脚本语法、配方 ID 唯一性、物品与流体引用、任务依赖无环全部通过静态检查。
- 六维在不使用洞穴工厂的前提下，从野外样本启动并保持正库存运行；重启存档后继续，不放区块加载器。
- 渊海实体测试覆盖 8 只海猪投喂、掉落物可以由玩家自建装置回收、实体损失后重新捕获，且长期运行不生成额外实体。
- JEI、FTB Quests 与真实客户端/服务端验证完成前，不把配方状态描述为已验证。

## 已知限制与假设

- `marine_snow` 的主链是 Sea Pig 实体循环，没有对应的 Create `_primary` 配方 ID；它只提供 `_recovery` 备链。这是本设计中唯一的实体主链。
- 海猪消化产出以掉落物形式生成，收集装置不由本设计提供；玩家自行搭建 Chute/Belt/Arm 即可，不因此新增方块或实体。
- 全部六维内容都不新增生物实体；需要调整生物行为时只走数据层或机制层，不新增模型与渲染资源。
- 18 项目标里有 17 项提供 Create `_primary` 配方。Create 的 Spout（`create:filling`）只允许单个输出，所以 `toxic/acidic_radrock_primary` 每轮产出 1 个而不是默认 2 个；Spout 的节拍由传送带与设备本体决定，仍满足 8 个/分钟的验收下限。
- 五维签名机启用前，对应残渣没有生存来源，因此这五条备链与任务中的“残渣回收”节点处于预览状态；任务已标记为可选，不阻塞分支。
- 精确数量、处理时长与并行度都在 Create 配方与 COMMON 配置中，接口名称与主备循环结构保持不变。
- 不新增自定义培育机、第三条机器模式、全局扫描或常驻 AI 农场。
