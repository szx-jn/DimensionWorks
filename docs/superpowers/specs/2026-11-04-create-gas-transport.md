# Create 管道运输 Mekanism 气体

## 目标和边界

机械动力的流体管道、机械泵及其网络应能运输所有注册的 Mekanism gas，包括其他模组和 KubeJS 注册的气体。按 1 mB 气体对应 1 mB 流体处理，沿用 Create 对流速、压力、分流和连接的规则。不同气体以及气体和液体不能混同。气体向世界排出时立即消散并产生上升粒子，不产生持久流体方块。

工作盆现有的两个气体缓冲、配方输入输出、盖子密封及流失规则保持不变。管道对盆进行气体输入或输出时，仍分别使用其进气和出气槽。Mekanism 原有气体管道也应继续正常工作。

## 实现约束

- Mekanism 的 gas 是化学品，不是 Forge 流体。Create 网络从方块实体的流体能力读取和写入 `FluidStack`，需要桥接气体能力，而不能仅添加流体标签。
- 桥接必须保留同侧已有流体能力及气体能力的访问权限、槽位和输入输出限制；特别是工作盆同侧可能同时提供两种能力。模拟操作不得修改气体，执行操作必须按实际插入或抽取的数量结算，并遵守整数范围。
- 一种可行方案是用带气体注册 ID 的内部代理流体栈承载气体；必须核对 Create 各处流体比较、过滤、渲染和序列化均保留并区分该 ID，不能仅按代理流体类型比较。无法识别或已移除的气体 ID 应安全拒绝，不能转换为其他气体。
- Create 的开放管口有独立的世界排放路径，不能只依靠普通流体方块逻辑。气体排放的模拟阶段不产生粒子或消耗气体，实际排放才消耗并在服务端通知客户端显示粒子。粒子数量应有上限，避免管道阵列产生无限特效或世界扫描。
- 适配器的生命周期应跟随原能力失效，避免区块卸载、方块替换或管道重连后保留过期引用。不得让其他流体系统意外把代理流体存为可持久气体方块。

## 验收

验证气体源到气体容器、盆到盆、盆与 Mekanism 机器双向传输；覆盖自定义气体、不同气体切换、同侧已有液体、管道分支、过滤、管口排放、堵塞及区块重载。检查模拟不扣气、拒绝输入不丢气、执行量守恒，气体排出后无方块残留并有粒子。复测工作盆开盖流失、关盖密封以及原有配方。还需验证专用服务器启动及客户端显示；未执行的游戏内场景不得视为通过。
