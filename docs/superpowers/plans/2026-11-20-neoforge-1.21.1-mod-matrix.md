## 核心阻塞及优先方案

- Alex 的六洞穴应优先保留。Raguto 2.0.10 端口和 AlexsCavesNeo 2.0.4 都不是官方；前者页面简介写五洞穴但其main源码树已见174个匹配糖果洞穴/相关实体的路径，不能据简介判定缺第六洞穴；其依赖独立 Citadel Port 项目 `XjY0RcQj`（现验证固定版本 `mIylVpkN` / 2.7.6），后者宣传六洞穴且依赖官方 Citadel。[main的ACBiomeRegistry.java](https://github.com/Raguto/AlexsCaves-1.21.1/blob/main/src/main/java/com/github/alexmodguy/alexscaves/server/level/biome/ACBiomeRegistry.java) 第23、25行已明确注册糖果洞穴并枚举六洞穴；仍须以2.0.10对应发布资产确认实际覆盖。配套维度端口 1.1.0 元数据固定依赖 Raguto 2.0.10，不能直接与新 Neo 端口互换。需要比较六洞穴、糖果洞穴、dimension/biome keys、实体与NBT；同名dimension并不证明可打开旧世界。
- Alex 端口许可须在采用前厘清：Raguto Modrinth 标 LGPL-3.0-only，而 GitHub [main/LICENSE](https://github.com/Raguto/AlexsCaves-1.21.1/blob/main/LICENSE) 实际被 GitHub 识别为 GPL-3.0；Neo 端口页面元数据 LGPL、说明正文 GPL 也冲突，源码 LICENSE 未成功取得。按发布资产实际许可及上游权利核实，不将第三方代码复制到本仓库。
- 当前源无目标候选的4项：`caves_delight`、`mekanismdelight`、`witherstormmod`、`kaleidoscope_sauce`。前三方需等待/许可fork移植或明示功能取舍；任何含其物品、机器、实体或方块的旧档不能直接删Mod。Wither Storm 原项目All Rights Reserved，未经许可不规划重新分发其源码/资源。
- 同名陷阱已排除：`caves-delight` (`ckMiR9Zc`) 是原版洞穴食品，原包 `caves_delight` (`FM6bfCfc`) 是Alex洞穴食品；`mekanism-delight` (`H7aqXBWR`) 与原包 mochi-753 的 `MekanismDelight` (`NEUFDicS`) 不同。同名新包不能算保留原内容；原 Mekanism Delight 已由独立 fork ccb1d24 移植，6 项原生 GameTest 通过，完整整包待验收。
- 本包三个 fork 已完成原生专项移植：CMP 62db6a8、TrueUUID b2fa749、厨房自动化 9053486；固定源码归档均已在独立目录重建且 JAR 逐字节一致。专项分别通过 19、13、23 项 GameTest 与客户端验证，完整合包/旧档仍待验收。用户禁止中途发行版，整包流水线须接入固定源码及校验和构建。ExtendedAE 官方目标资产仍需核对原注册内容。
- 客户端保留光影功能：放弃旧Mekalus/Oculus实现，使用Iris+Sodium的目标版本链；当前Embeddium也有目标版，但不能与Sodium同时安装作为兜底。颜色轮、Iris Shader Folder、SodiumExtras的依赖链一起调整。
- LDLib候选已是LDLib2代际。NeoEcoAE 21.2.18要求AE2>=19.2.17、LDLib2>=2.2.40，不能只改版本字段。KubeJS Create/Mekanism仅beta候选，应作为有条件采用并跑全配方验收。
