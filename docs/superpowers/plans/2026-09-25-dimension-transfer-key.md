# Dimension Transfer Key Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a KubeJS dimension key that permanently unlocks a configurable key binding for entering `dw:transfer`, with return-to-source behavior.

**Architecture:** KubeJS owns the consumable item and grants a persistent vanilla entity tag. The self-owned `dimensionworks-transfer` mod owns server-side access checks, return-point persistence, the configurable client key binding, and a dedicated client-to-server network request. The OP2 command is a separate administrative path that bypasses the tag.

**Tech Stack:** Minecraft 1.20.1, Forge 47, Java 17, KubeJS 2001.6.5, Gradle, Python standard library.

**Spec:** `docs/superpowers/specs/2026-09-25-dimension-transfer-key-design.md`

## Global Constraints

- Preserve Minecraft `1.20.1`, Forge `47.4.16` for the self-owned mod compile target.
- Do not modify third-party source or generated launcher binaries.
- Item id is `kubejs:dimension_key`.
- Permanent access tag is `dimensionworks_transfer.unlocked`.
- Key mapping id is `key.dimensionworks_transfer.toggle`; default is `P`.
- Return points must survive server restarts.
- `/dwtransfer` requires permission level 2 and bypasses the permanent unlock tag.
- The key binding uses a dedicated network packet and does not execute `/dwtransfer`.
- No item recipe is added in this phase.
- Textures are generated by Python, not committed as an unexplained binary edit.
