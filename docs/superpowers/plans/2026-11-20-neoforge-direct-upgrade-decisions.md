# NeoForge 迁移：直接升级优先与待确认取舍

2026-11-20 用户补充约束：优先采用可以直接升级使用的版本；找不到升级版、需要自行实现的项目必须先汇报，不得直接开始新增移植。此要求替代此前按全内容保留目标自行选择第三方 fork 的执行方式。禁止中间发行版、停止光影专项及保全玩家/服务器存档的要求继续有效。

## 现成版本优先

已取得并校验的候选资产包括 150 个 Modrinth 版本及 15 个 CurseForge 文件；其中有新版必需库，因此不能直接将资产数与原清单项数相加。整包目标清单尚未正式切换，原清单仍是 Forge 基线；不得在此状态生成混合平台整包。

### 其他发布源补查：有现成替代，不等于原内容升级

收到用户再次强调先找现成版本后，重新查询上述四个原 Modrinth 项目的精确目标版本，仍均为零；另核对原 MekanismDelight 作者 Mochi753 的 [CurseForge 项目 1415001](https://www.curseforge.com/minecraft/mc-mods/mekanismdelight)，发布页面和文件索引也未列目标版本。搜索页中的相邻模组版本不能作为本项目的版本证据。

洞穴料理找到两个可直接取得的替代候选。仅下载核对发布文件，校验文件大小、SHA-1 并读取原生模组元数据和物品模型路径；没有安装、运行或修改其源码，也没有加入清单。

| 现成替代候选 | 固定目标资产 | 与原 `caves_delight` 的差异 |
|---|---|---|
| FixerLink1 的 Alex's Caves Delight | [1.0.28 / 文件 7649611](https://www.curseforge.com/minecraft/mc-mods/alexs-caves-delight/files/7649611)，项目 1035901 | JAR 声明 `alexscavesdelight`，108 个物品模型路径。与原 JAR 的 71 个物品模型路径只同名 3 个，另外 68 个未同名；不同注册命名空间，不能直接接管原物品或旧档。可评估作为洞穴料理替代，而非原插件升级。 |
| RT_02 的 Alex Caves Delight+++ | [2.2.0 / 文件 9539489](https://www.curseforge.com/minecraft/mc-mods/alex-caves-delight/files/9539489)，项目 1754099，资产名 `acd671.21.1.jar` | JAR 声明 `cavern_kitchen`，83 个物品模型路径，与原 71 个模型路径没有同名项。页面环境写 Client，不能据此保证服务器适用；依赖及料理行为待核对。暂列替代候选，不安装。 |

模型路径计数不是物品注册数量，也不是行为覆盖率：原 JAR 还包含投掷物模型。上述比较只证明两个候选不能按同名原物品直接升级，尚未完成配方、食物效果、方块和旧档映射审查。优先评估现成替代的覆盖与维护成本，再由用户决定是否接受内容变化或批准精确移植；不得因为原项目零版本就直接开始自行制作。

封存的当前服务器快照中，前三项未发现实际方块、实体或物品栈引用。该结果仅覆盖已审计的服务器，**不能推断所有玩家的本地单人存档都没有这些内容**；若决定舍弃，迁移预检必须报告本地旧档引用并阻止静默丢失。

以上三项不是必须新造的基础依赖。默认暂缓接入它们，继续现成目标版本的整包适配；不因已经投入移植时间而自动采用。用户确认前，不新增第三方移植、不继续洞穴料理公开提交，也不以功能减少为由跳过旧档保全。

## 下一步执行边界

1. 继续固定现成目标资产及完整依赖闭包，逐项处理当前脚本、配置、标签、配方和资源引用。
2. ExtendedAE 采用现成官方版本。原服务器唯一无限元件的真实 NBT `record` 是 `ae2:i / minecraft:cobblestone`，对应新 `extendedae:infinity_cobblestone_cell`；不能按默认水元件映射。其余注册名及库存组件也需转换。
3. 一次性存档转换只操作新建副本；对账玩家身份/库存、世界方块、实体、AE2/Mek 存储和整包持久化数据。禁止直接用目标游戏打开封存原档或生产原档。
4. 遇到新的“无现成版本且必须自行实现”项目，先列原来源、查询结果、无法保留的具体行为和可选取舍，等用户确认后再开始。
