# 服务端指南

本指南面向准备部署或维护 DimensionWorks 多人服务器的服主与管理员。

## 1. 确认运行环境

当前正式版基线：

| 项目 | 要求 |
| --- | --- |
| Minecraft | 1.21.1 |
| 加载器 | NeoForge 21.1.267 |
| Java | 21 |
| 整合包版本 | 必须与玩家客户端匹配 |

服务端包已包含对应版本的服务端运行文件与启动入口。服务器主机需要能够运行 Java 21，并具备足够的磁盘空间、内存和稳定网络。实际资源需求取决于在线人数、世界规模和自动化工厂规模。

## 2. 下载服务端包

1. 打开 [DimensionWorks Releases](https://github.com/szx-jn/DimensionWorks/releases)。
2. 选择准备部署的正式版。
3. 在该版本的 Assets 中下载 `DimensionWorks-Server-版本号.zip`。
4. 将压缩包解压到独立的服务器目录。压缩包根目录可直接作为服务端目录使用。

请确认下载的是服务端 ZIP，而不是客户端 `.mrpack`。每个 Release 实际提供的资产可能不同，以该版本的资产列表和发行说明为准。

## 3. 首次启动

### Linux

在服务端目录中执行：

```sh
bash start.sh
```

### Windows

在服务端目录中运行：

```bat
start.bat
```

首次启动前，先阅读 Minecraft EULA。只有在你同意 EULA 后，才能将生成的 `eula.txt` 中的 `eula=false` 修改为 `eula=true`，然后重新启动服务器。

首次启动会生成运行配置和世界文件。建议先在隔离测试目录中完成首次启动、配置和连接测试，再迁移或创建正式世界。

## 4. 基础配置

服务器首次运行后，根据实际需要检查并配置：

- `server.properties`：服务器端口、最大玩家数、游戏模式、难度、白名单及在线验证等基础选项。
- `ops.json`：管理员名单。
- `whitelist.json`：白名单（启用白名单时）。
- `config/`、`defaultconfigs/` 和世界目录中的 `serverconfig/`：整合包及世界级配置。

修改配置前先停止服务器，并保留原文件副本。不要把账号凭据、认证密钥、玩家隐私或运行时数据提交到公开仓库。

### 网络与登录

- 默认 Minecraft Java 版服务器端口通常为 TCP 25565；如果你修改了端口，应同步调整防火墙和路由器端口转发。
- 仅向可信玩家开放管理权限；公网服务器建议启用白名单并限制管理端口。
- `online-mode`、皮肤/认证服务及整合包身份验证相关设置会影响玩家登录。请按当前服务器实际采用的认证方案配置，不要仅为解决登录问题就随意关闭在线验证或删除身份数据。
- 客户端与服务端应使用同一个 DimensionWorks 正式版。不要让玩家混用不同版本的 Mod 或配置。

## 5. 备份与更新

### 日常备份

定期备份至少应包括：

- 完整世界目录；
- 服务端配置及白名单、管理员权限文件；
- 认证方案所需的身份数据和相关配置；
- 服主自行维护的脚本、插件或其他自定义内容。

备份前应正常停止服务器，或使用经过验证的一致性快照方案。不要在服务器持续写入世界数据时简单复制文件并把副本视为可靠备份。定期在独立目录中测试恢复流程。

### 更新版本

1. 阅读目标 Release 的发行说明，确认服务端 ZIP、更新包及迁移说明。
2. 停止服务器，并备份整个当前实例。
3. 首次部署新 Minecraft / 加载器版本时，优先按发行说明建立独立的新实例；不要直接覆盖旧服务端目录。
4. 仅在发行说明明确支持时使用增量更新包或更新器。
5. 在测试实例中验证启动、玩家登录、世界保存与重启后，再切换正式服务器。

跨 Minecraft 或加载器版本迁移可能涉及世界数据、玩家身份和模组数据。不要把“服务器成功启动”视为存档迁移完整的证明；迁移前必须保留可恢复的冷备份。

## 6. 运行维护

- 定期检查服务端日志、崩溃报告、磁盘空间和备份状态。
- 大型自动化工厂和持续加载区域会增加服务器负载；限制不必要的区块强加载，并监控长期运行表现。
- 发生崩溃或异常停服时，先保留日志和现场副本，再进行修复；避免在唯一世界存档上反复试错。
- 不要公开分享包含令牌、认证信息、玩家 IP 或其他隐私数据的日志。

## 7. 故障反馈

向项目反馈服务端问题时，请提供：

- DimensionWorks 版本及服务端操作系统；
- Java 版本和启动方式；
- 在线人数及问题发生时的操作；
- 完整服务端日志、崩溃报告和可复现步骤；
- 问题是否只发生在特定世界、玩家或自动化区域。

反馈入口：[GitHub Issues](https://github.com/szx-jn/DimensionWorks/issues)。
