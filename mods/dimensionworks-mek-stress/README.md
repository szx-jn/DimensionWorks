# DimensionWorks ME Mechanical Power

Minecraft 1.20.1 / Forge / Java 17。通过自研 Mixin 接入 Create、AE2、Applied Create 与 Mekanism，不修改第三方模组源码。

## 0.3.25：跨维物流与 SU 传输

- 新增三级单方块 Create SU 传输端（纹理逐级增加工业结构细节），输入端按真实 RPM 作为应力负载，输出端跟随输入 RPM 提供已分配容量；输入端不设置 RPM。每个频道严格绑定一对设备，优先级依次分配已实际消耗的 SU，禁止同一 Create 动力网络把本设备输出回灌成输入。
- 物品和流体通过 Forge 标准能力接入，频道库存与吞吐额度由两端共用。三级分别为 50/150/300 个物品每秒与 50/150/300 B 每秒；每秒按 20 tick 结算。频道基础容量为 27 个物品槽和 16 B 流体；共 20 个容量升级槽，物品卡每张增加 27 槽，流体卡每张增加 32 B。
- 拆掉最后一个端点时，频道库存打包成有限大小的物质球，统一发送到频道所有者的持久云盘（不自动放入背包），由 F12 界面主动领取，再通过物质球解包器重新接入普通物品/流体自动化；大于 16 B 的单种流体会拆分到多个物质球。洞穴工厂流体仍须装入安瓿，安瓿进入频道时开始稳定计时，过期后结算为空瓶和来源维度残渣。
- AE2 量子桥、Mekanism 量子纠缠传输器和 Create More: Package Couriers 的跨维固定网络/纸飞机路线均按维度 ID 过滤：同维允许，跨维仅主世界、下界、末地互通。AE2 无线终端不经量子桥连接限制。Create Mobile Packages 的机器人由其固定版本按维度保存物流数据，且禁止机器人跨维旅行。
- 三档生存配方尚未加入；确认中、高级材料方案前暂不注册配方。代码编译和单元测试已通过，仍需完成包含整合包实际模组的启动与游戏内物流/应力验收。

## 0.3.24：工厂小数产量与升级梯度

各等级默认目标转速统一为 1024 RPM；动力按机器并行数计费，升级后同转速的理论产能递增。物品产出的小数余量按输出槽和物品累计，只在实际输出时结算；卸载或重启不保留不足一件的余量。已有实例使用旧的自定义目标转速时需自行更新配置。详细模型和验证范围见[工厂转速与升级设计](../../docs/design/mekanism-factory-progression.md)。

## 0.3.23：Mek 工厂等级产能

超速产物倍率按等级从基础 1.25 到终极 2.0（10240 RPM）递增，保留原版并行。该版本的整数产物每次向下取整；0.3.24 已增加物品小数余量累计。等级目标、计算公式、配方成本和验收限制见 [工厂转速与升级设计](../../docs/design/mekanism-factory-progression.md)。

## 0.3.22：Create 管道运输气体

Create 的流体管道和机械泵可以与相邻 Mekanism 气体能力交换所有已注册 gas，数量按 1:1 转换；沿用管道压力、流速和分流。管道内部使用带气体注册 ID 的流体栈区分气体，不需要为每种气体预先配置映射。支持普通液体和气体能力存在于同一方块侧面；原能力的输入、输出限制仍然有效。智能管道可使用装有目标气体的 Mekanism 气体容器作为过滤条件，气体种类始终分别匹配。工作盆的两个气体缓冲、配方和密封/流失处理不变。

开放管口和软管滑轮向可替换空间排放气体时直接消散并显示上升烟雾，不产生气体方块。排放模拟不产生粒子或消耗气体；堵塞或区块未加载时不排放。排放粒子按每次传输限制数量，不增加世界扫描或区块强加载。普通液体仍按 Create 原有规则处理。

## 0.3.21：修复小数能耗误报

机械供能的配方计算修正 Mekanism 对小数能量整除的低估：预算刚好足够时，安装升级后仍可正常加工；预算不足与动力过载仍会阻止加工。

## 0.3.20：统一 FE/t 与机械应力

- 统一 `1 FE/t = 2 SU`。Mekanism 的 J 先经过当前 J/FE 配置换算；不再把最大传输上限当作实时发电量。
- 普通发电机完整运行原版子类 tick 后计量实际产电，内部旧库存不参与换算。太阳能底面、风机前/底面等原生输出面可连接普通轴；同一 Create 网络的多个输出轴共享一个应力池，接入多个独立网络时才平分总产电。无燃料、无日照或不满足原版运行条件时不产生机械容量。
- 工业涡轮阀门与聚变输出端口也接入相邻普通轴。共享结构每 tick 只计量一次，全部已加载输出轴分摊总量；仅外侧端口有效。原生电缆导出被拦截，临时发电缓冲在计量后清空，避免电能/应力重复输出。
- MEK 加工机器的额定负载改为原版当前 J/t 经 FE 换算后 ×2，包含工厂进程数、升级、即时化学配方并行和可调电阻炉能耗；再按实际 RPM / 目标 RPM 缩放。虚拟能源有每 tick 的有限预算，模拟不扣、执行才扣，不能重复提取；预算在原版更新之前按已付费的应力冻结。
- 超速配方产物向下取整，避免取整创造未经计费的燃料。
- 低于目标转速时先积累足额机械工时再推进一次原版更新；卸载、重连或变速不能反复获得免费首 tick。
- 激光发射器按原版 J/t 计费；放大器与牵引光束继续使用真实的内部光束缓冲，不会因接轴获得满能量。SPS 输入端口允许接轴，1024 RPM 时额定预算为原版端口容量的 1/400 J/t，按转速缩放，保留原版线圈与反物质算法。传送机在原版计算目的地/实体成本后先申请对应 SU，供给不足时不能传送。
- AE2、ExtendedAE 和 NeoECOAE 继承的方块 FE/RF 输入统一拒绝，改由 AE 网供电；物品充能能力保留。
- AE 应力能源接收器按其真实机械负载 ÷2 转 FE/t，再经 AE2 当前 FE/AE 比率注能；过载、断轴和零转速停止注入，正反转等价。
- 龙堆输入不再免费补盾或固定消耗 256 SU/RPM。每 tick 只使用输入网络剩余容量 ÷2 对应的 FE，经原版 `injectEnergy` 充能/补盾；原版温度效率与故障机制保留。所有机械发电轴使用同一来源控制器，避免 MEK/龙堆相互移除来源。
- 只访问已加载邻接块与原版登记阀门，无世界扫描、强加载或新增实体。普通发电机每次检查六面，多方块每 tick 仅遍历原版登记阀门建立共享端口快照；源端变化立即同步关联轴。

验证入口：`gradle build` 为单元测试；`gradle energyProbeJar reobfEnergyProbeJar` 生成独立生产客户端探针。探针仅放入可丢弃实例，加入 JVM 参数 `-Ddimensionworks.energy.probe=true` 自动创建 `dw-energy-probe` 世界，并输出 `energy-probe-result.txt` 与截图。探针会放置设备、强制加载测试区块并修改测试配置，不得用于玩家存档，也不进入正式主 jar。具体实测结果见 `docs/validation/2026-11-03-energy-unification.md`。

## 0.3.19：修复发电机启动注入

Mekanism 10.4.16.80 的 `CableUtils.emit` 接受 `Set<Direction>`，禁止 FE 输出的 Redirect 按该签名匹配，避免误写为 `EnumSet` 导致发电机类加载失败。保留严格注入检查；发电机仍通过相邻转轴输出应力，不向电缆发送 FE。修复不增加区块加载、实体或扫描任务。

## 工作盆气体反应与混合产出

工作盆具有两个各 10,000 mB 的气体缓冲：槽 0 保留为出气（可抽取，不接受管道灌入），槽 1 为进气（可灌入，只由配方消耗）。出气保存在 `DimensionWorksBasinGas`，进气保存在 `DimensionWorksBasinInputGas`，两者按当前槽位职责独立读写。每个缓冲只能存一种气体。

气体输出标记 `gas_output` 现在可与普通物品、液体混合产出。NBT `Gas`/`Amount` 指定气体产出，可选 `InputGas`/`InputAmount` 指定气体输入。先模拟检查进气数量/类型和出气容量，再交给 Create 检查普通产物空间；匹配模拟不修改气体，实际产出才扣除进气、存入出气。气体进出或流失会通知工作盆重新匹配配方，以便供气恢复或排空出气后继续加工。

纯消耗气体的配方使用 `InputOnly: true`，并只填写 `InputGas`/`InputAmount`。该模式不要求也不占用出气缓冲，适合把气体作为一次性反应物；缺少对应气体时配方不会匹配或扣料。

铜还原示例：普通加热，1 氧化铜 + 250 mB CO → 1 铜锭 + 250 mB CO₂，禁止超级加热。供气通过管道从制气盆送入反应盆，另一条抽气管取出 CO₂。进气缓冲只接受灌入；切换原料气体前应先通过对应配方消耗完已有进气。

需在 Actions 构建及游戏中核对：250 mB 供气恰好消耗、缺气不扣料、出气满时不扣料、铜锭输出堵塞不扣气、反复模拟不产物、普通/超级加热切换、连续供排气和存档重载。未新增实体或世界扫描。

## 工作盆气体流失与密封

工作盆气体缓冲对所有 Mekanism 气体统一执行流失：无盖或开盖时，每 20 游戏刻合计扣除 200 mB，按两个缓冲当前存量比例分摊，总量不足时清空；只有盆正上方关闭的 `createdieselgenerators:basin_lid` 阻止流失。屋顶、普通方块和搅拌器不算密封盖。按游戏刻计时，区块卸载期间不结算，也不在重载后补扣离线损失。

计时由已加载工作盆现有 tick 驱动，每 20 刻检查一次盖子，不增加世界扫描。生产气体不触发额外扣除；空盆或盖子关闭时仍推进检查时钟，避免开盖后累计扣除。该规则只影响气体缓冲，液体不受影响。Java 改动需构建后进行游戏内验证，包括无盖、屋顶下无盖、盖子开合、少量余气和连续产气场景。

## 工作盆气体配方的温度限制

气体输出标记支持可选 NBT `ExcludeSuperheated: true`。设置后，工作盆在超级加热状态下会拒绝该标记，匹配模拟与实际产出均检查，避免 Create 普通加热配方在超级加热时抢占其他路线。未设置时保持原有行为。

木炭气体配方使用这一限制：普通加热产出 125 mB 一氧化碳，超级加热产出 250 mB 二氧化碳。两条路线各消耗 1 个木炭。限制仅在配方输出检查时执行，不增加扫描或 tick 任务；切换气体前需抽空工作盆气体缓冲。

## 0.3.15：输入应力扣除上限 99%

- 默认配置与 `config/`、`defaultconfigs/` 同步为 `maximumInputLossBasisPoints = 9900`；有效配置范围为 0～9900，代码的累计扣除、输入换算与配置读取也都以 99% 为硬上限。
- 各卡型的单卡损耗与 RPM 倍率不变。扣除作用于全网实时原始输入一次，不按 tick 反复消耗；零输入仍为零，保留比例在整数 SU 换算时可能向下取整为零，不保证至少剩余 1 SU。
- 添加/更新单元测试覆盖 99% 边界、旧 100% 参数、`Long.MAX_VALUE` 累计/输入、低 SU 的余数结转，以及扣除后输出恰好足额和超额的判定。测试仅在 Actions 中执行，本机不编译。
- 已有实例的有效自定义上限会保留；采用新默认时同步配置为 9900。超出 99% 的旧值由配置校验及运行时钳制保护。
- 不新增网络扫描或 tick 任务；仍只处理已参与的驱动器和齿轮箱，计算复杂度与原实现相同。

## 0.3.13：龙神反应堆机械能源桥接

龙之进化 1.20.1 的反应堆只通过 Create 应力运行，不依赖旧 FE 网络：

- 注入器背面直接连接普通 Create 传动轴。与 Mekanism 虚拟动力规则一致，输入网络占用 **256 SU/RPM**；冷启动时必须有外部应力源；启动以后允许用反应堆自身的 SU 输出回供护盾，且该回路的输入占额仍由 Create 原生过载机制计算。失去动力或网络过载后，虚拟护盾补能停止。正常停机时输出会立即停止，安全停机需要其他外部动力维持护盾直到冷却。
- 稳定器背面直接连接普通 Create 传动轴，成为 **256 RPM** 的动力源。反应堆总容量等于当 tick 的原版 **FE/t × 2 SU**，由所有已接入的稳定器轴均分，避免四倍发电。普通 Create 轴线之外不需要额外转换方块。
- 不再向外输出 OP/FE，也不接受外部 OP/FE 注入。核心内部的饱和度、护盾和温度继续由原版算法计算；运行期产生的能量按当 tick 原始发电值从内部饱和度扣除，避免因无法导出 FE 导致发电停止。正常停机时不再扣除输出能量，以保证饱和度能恢复。
- 虚拟 SU 输入激活后使用原版 `injectEnergy` 完成充能阶段，并在运行及停机阶段补充护盾至至少 95%。保留 5% 余量以免原版 `fieldInputRate` 除数归零。无 SU 输入时原版护盾耗尽、失控和爆炸逻辑完全不变。
- 使用普通轴、端口轴向一致且相关区块已加载；齿轮之心的现有 RPM 和应力额度限制继续生效。该实现没有绕过服务端原有限额机制。
- 已绑定且正在输出的稳定器轴使用弱引用正缓存核心和稳定器，重复查询会校验区块加载、方块实体身份、朝向、绑定组件和运行状态；发电率与有效输出轴数仍按实时值计算。未绑定的首次查询仍会按原版最大距离寻找核心，且不强制加载区块。

后续需在游戏内验证：构建与充能、四路应力分摊、Create 网络过载及恢复、正常停机、失去输入动力后的原版故障行为。这里的静态代码及数学测试不等于完成游戏内测试。

### 反应堆安装与验收

1. 按原版搭建一个核心、四个稳定器、一个注入器；各组件必须朝向核心，结构初始化有效。
2. 向核心放入觉醒龙锭（或九粒、一个觉醒龙块等价量）；启动前将外部 Create 动力轴接在注入器背面，确认网络没有超载。此输入占用 256 SU/RPM。
3. 按 Charge → Activate 顺序启动。等反应堆进入 RUNNING 后，将 Create 普通传动轴接在稳定器背面，转速固定为 256 RPM；可选择接入多路输出。
4. 四路输出总应力容量始终按照核心发电显示的 FE/t × 2 计算，不能把每一路都误认为总容量。
5. 运行中可通过 Create 网络将一部分自身输出回供注入器，但必须按 Create 应力负载真实计费。安全停机时建议保留独立的外部动力，确保护盾供能不中断直至冷却。
6. 实际游戏内验收还需覆盖：单端与多端产能分摊、输入过载、区块重载、冷启动、正常停机。**构建通过不代表上述行为已游戏内实测。**

## 0.3.12：实时应力额度

ME 应力不再是可积累的能源库存。内存卡和驱动器均不提供任何 SU 容量，旧存档 StoredSu 不再读取、写入或恢复供能；旧 StressKey 存储服务不再挂载。

- 原始上限 = 当前有效 IMPORT 齿轮箱的应力之和。Applied Create 面板的应力参数是 SU/RPM 系数，因此贡献为该系数乘当前有效机械转速。
- 有效上限 = 原始上限 × (1 - 输入扣除比例)。各卡的扣除贡献累加，默认全网最多扣除 99%，可配置为 0～99%。扣除只修正实时上限一次，不按时间累计。
- 输出占额 = 每台在线 EXPORT 的设定 SU/RPM 系数 × 经玩家上限约束后的设定 RPM。多台输出的占额相加；这是固定占用，不是 SU/t 扣费。设定为零、拆除或离网即释放占额。
- 剩余额度 = max(有效上限 - 输出占额总和, 0)。所有输出刚好用满时仍正常运行。
- 有效上限为零，或者输出占额总和超过有效上限：全部 ME 输出停机，驱动器界面、Jade 与齿轮箱工程师护目镜提示“应力输出过载”。
- 输出转速总和超过全网 RPM 上限：全部输出停机，提示“输出转速过载”。不按比例降速，也不让先 tick 的设备抢走额度。恢复足额配置或供给后自动恢复。
- 下游 Create 负载超过某台 EXPORT 宣告的容量，仍由 Create 原生过载机制处理。AE 的物品、流体等其他服务不因应力过载停止。
- IMPORT 必须有有效机械动力且 Create 网络未过载，同时 AE 节点供电、有频道、已加载。停机、改值、拆除与离网实时重新计算；不依赖旧的十 tick 需求扫描。
- 禁止 ME 输出回灌为新输入，包括不同 AE 网络之间的回灌：输入所在的机械网络有 ME EXPORT 源时不计入输入。

齿轮箱保留 Applied Create 的模式与设置面板。ME 输出不再调用按流量插入、提取 StressKey 的旧方法；AE 自身仍需正常供电与频道。

## RPM 驱动器与卡

每个逻辑 AE 网络最多两台有效驱动器。驱动器只提供基础 RPM，卡只提供额外 RPM 并扣除输入应力上限。

| DDR | 槽位 | 驱动器基础 RPM | 每张均衡卡增加 RPM |
|---|---:|---:|---:|
| DDR1 | 4 | 256 | 256 |
| DDR2 | 8 | 512 | 512 |
| DDR3 | 16 | 1024 | 1024 |
| DDR4 | 32 | 2048 | 2048 |
| DDR5 | 64 | 4096 | 4096 |

卡型 RPM 系数：劣质 0.25×、经济 0.5×、均衡 1×、高速 2×、低损耗 0.5×、最终 4×。例如 DDR1 装四张均衡卡时上限 1280 RPM，装四张高速卡时上限 2304 RPM；两台驱动器贡献相加。

每卡输入扣除：劣质 20%、经济 2%、均衡 1.5%、高速 1.75%、低损耗 0.75%、最终 0%。默认网络总扣除封顶 99%，代码硬上限同为 99%，不会因超额插卡或旧 100% 参数而完全扣尽输入。低损耗型使用 `low_loss` 注册 ID，不提供储存容量。正常卡手工制造仍有 25% 劣质概率，AE 自动合成假玩家继续豁免。

共同制作门槛为 AE 工程处理器与 Mekanism 强化合金。高级控制器保留 Create 精密构件与坚固板配套；驱动器升级只消耗一台前级驱动器，普通 DDR5 卡取消反物质。四种正常卡均可四张同类型前级卡加新材料升级，保留旧投入；最终卡仍没有毕业配方。

驱动器升级保留物品中的内存卡数据；卡仍须与驱动器同代才提供贡献，需要另行升级。当前实现不读取或清理 `StoredSu`。

## 界面与接口

- 驱动器仍为每页 4×5 卡槽，背景按实际 176×215 纹理采样；标签和数值位于同一个等宽信息框。显示原始输入、输出占额、剩余/有效上限与 RPM 上限。DDR5 最后一页只有四个有效槽位。
- 客户端容器数据使用四个 16 位字传输每个 long；页码和可见槽内容同步，快速翻页不修改客户端方块实体的绝对卡槽。
- Jade 显示网格即时分配；每台齿轮箱也显示原始输入、全网占额/有效上限及总输出 RPM/上限。
- /dw memory 查询附近已加载驱动器的实时分配，不加载新区块。
- IMemoryGridService.snapshot 返回 capacitySu（原始输入）、effectiveCapacitySu（扣除后）、allocatedSu（占额）、availableSu（剩余）、demandRpm 与 bandwidthRpm；旧 insertSu/extractSu/reportGearboxExport 接口已移除。
- DDR1–DDR5 驱动器使用完整 16×16×16 方块模型，所有机箱表面贴图均完全不透明，正面状态灯位于机箱外侧，避免边缘缺口与透视地下。Python 生成脚本同步保留这些约束；不增加实体、区块加载或服务端每 tick 开销。
- 内存卡保留 64×64 透明纹理。原稿位于 scripts/assets/memory_cards_reference.png；使用 scripts/requirements-memory-assets.txt 环境运行 scripts/draw_memory_assets.py 可重建。

## MEK 机械动力

Mekanism: Generators 发电机的原生能量输出面（包括太阳能底面）可直接连接朝向输出口具有轴连接面的 Create 动力部件，默认按正向 32 RPM 提供应力容量；FE/t 按 1 FE/t = 2 SU 换算，SU/RPM 系数为实际输出 J/t 经当前 J/FE 换算后 × 2 ÷ 32，再由接入的动力部件分摊。发电机仍执行燃料、环境与产能逻辑，原生 FE 电缆外送被拦截，避免 FE 与 SU 双重输出。只在能量输出面建立动力源，其他侧不产生应力。具有自身发电逻辑的 Create 部件暂不接入此桥接，避免覆盖其原有动力源。

合格加工机器继续只接受相邻 Create 动力网络；ME EXPORT 是可选供能源之一。有效 RPM 受玩家/齿轮之心与 directMaxRpm 限制；基础、高级、精英、终极默认目标转速均为 1024 RPM；旧实例的自定义配置可覆盖该值。0.3.20 起应力按原版 J/t → FE/t → SU 换算，正反转等价。

机器作为虚拟成员加入真实 Create 应力网络。低于目标时按 RPM 比例减速，超过目标时按比例放大配方吞吐，输出边界仍检查容量和最终产物额度。FE/J 供能和旧储能元件保持退役，Jade 隐藏 Mekanism 原生能量条。虚拟能量使用有限的每 tick 预算且不写入 NBT；动力路线仅检查已加载区块并在单台机器当前 tick 内复用，避免存档时递归触发区块读取。

`mekanism:energy_tablet` 的原生工作台配方被替换为 Create 金属注液与顺序装配，成品仍使用 Mekanism 能量板并保持 FE/J 恒为 0；下游配方继续消耗该物品，不再使用 `kubejs:energy_plate`。能量立方与感应储能元件的退役规则继续有效。配方与边界见 [能量板工业制造](../../docs/design/energy-plate-production.md)。

## 性能与配置

AE 服务只跟踪驱动器和齿轮箱参与节点，不再反复扫描输出端下游机器。一个服务器 tick 内的重复 snapshot 读取复用同一结果；服务在 tick 开始建立本 tick 快照，已知输入变更会使其失效，tick 结束只在失效时刷新。Create 网络回调只通知订阅该网络的 AE 服务；网络合并/拆分时齿轮箱成员钩子补登记对应服务，避免每次动力网络更新遍历所有 AE 网格。重入保护防止传播递归，输出状态仅在变化时写回 Create。新增内容不创建实体、不强加载区块，也不逐 tick 写入应力库存。

配置在 config/ 与 defaultconfigs/ 的 dimensionworks_mek_stress-common.toml。更新已有实例时需要同步基础 RPM、卡 RPM 与 maximumInputLossBasisPoints；旧容量及 storageExponent、efficiencyExponent 配置已停用。客户端、服务端需要同时更新此版本的菜单协议。

## 0.3.17：拓扑边显示与成员剪枝缓存失效

依赖 RPM Limit 0.4.16 或更新版本。虚拟成员与物理成员使用同一套 source 父索引，拓扑图不再隐藏虚拟机器到接入轴的合法连接；右栏区分 source 边、当前页可解析边和跨页/缺失上游。

应力重算发现失效虚拟成员或已被世界替换的物理成员时，会通过 RPM Limit 的统一入口失效网络缓存。下一次限速计算重新扫描当前成员，避免旧的最低 RPM 上限在成员卸载后继续约束整个网络。该处理不改变 Create 的原生 source 图，也不加载新区块。

## 0.3.16：虚拟负载恢复与拓扑诊断

依赖 RPM Limit 0.4.14 或更新版本。虚拟机器和反应堆输入成员统一标记为运行时成员，不进入 Create 物理成员的持久化总账；重启重新接入时避免重复计费。反应堆输出轴同时维护 `lastCapacityProvided`，恢复时不再漏记已提供容量。反应堆输入负载按接入网络最低 RPM 上限核算。

蹲下持扳手左键已接入动力的 Mekanism 机器，可打开对应应力网络拓扑；虚拟机器节点保存其实际接入端坐标，显示到来源方块的连接。`MachineKineticRegistry.sync(machine, network, rpm, attachment)` 明确接收实际接入坐标；所有调用统一使用该四参数接口。

## 0.3.26：传输端可用性修复

一级跨维传输端和物质球解包器提供 3×3 Create 机械合成配方，材料只使用 Create 与 Mekanism；中高级传输端继续无配方。倍率支持输入 0.01–1000000 SU/RPM（最多两位小数），点击应用或回车提交，服务端验证当前菜单、距离和频道权限。转速仍只取实际轴速。修复传输端轴向方块状态与 Create tick 生命周期；即使只有输入端，也必须读取真实转速并承担输入负载，倍率变化即时刷新真实网络应力。专属物品统一归入 `dimensionworks_cave_factory:main`「维度工坊」页签。

频道绑定同样使用验证过的完整整数配置消息，避免原版菜单按钮协议的单字节按钮编号截断 1–1024 频道值。补齐 Jade 齿轮箱配置翻译，避免开发客户端配置检查失败。可用 `-Ddimensionworks.verifyTransportModels=true` 启动开发客户端验证全部七种放置状态模型与贴图，检查通过后自动退出；验证代码不进入发布 JAR。


## 云盘回收（0.3.27）

最后一个端点拆除后，频道物品/流体打包成物质球，连同退还的容量升级统一写入频道所有者 UUID 的云盘。在线玩家每次投递收到一条红色系统文字；离线投递在下次登录补发，物品不自动进入背包。云盘写入主世界 `dw_cloud_disk` SavedData，关闭界面、下线或重启均保留未领取内容。

默认 `F12` 打开云盘，每页 27 个物品预览。点击或 Shift 点击主动领取至背包，空间不足时保留余量；不允许向云盘塞入物品、把预览拿到光标或丢弃预览。服务端检查当前菜单与所有者身份。预览只同步物质球的类型数量，完整库存 NBT 留在服务端，领取时才同步真实物质球；没有新实体、强制加载或每 tick 全量扫描。

红色提示：`你有一个频道完全损坏了......，这个频道的物品已经打包成物质球发到你的云盘了，可以点击f12打开云盘界面获取物质球`

云盘加入前的旧内存队列会随旧进程结束而消失，代码更新不能从已经消失的队列重建物品。新版持久存储避免后续重启丢失。可选 `gradle -PcloudRuntimeChecks runGameTestServer --no-daemon` 在独立 `run-gametest-cloud` 世界检查保存/加载、完整 NBT、UUID 隔离、重复领取、背包无空间与部分领取、升级堆叠拆分和逐次通知；实际 F12 与点击操作仍需客户端验证。
