# DimensionWorks RPM Limit API

组合开发环境使用 `devJar` 任务生成官方映射开发 JAR；生产服使用普通构建 JAR，不安装 `-dev.jar`。ME 动力模组的 GameTest 会自动使用此开发变体。

## Default
New players start at **32 RPM**. The hard maximum is **10240 RPM**.
The mod declares Create as a `BEFORE` dependency and its Mixin configuration is required, so the Create kinetic hooks are applied before Create's content is loaded.

## 齿轮之心

RPM Limit 模组承载 KubeJS 齿轮之心的工业额度运行时。物品由 `kubejs` 注册，Java 只按装备者 UUID 聚合当前加载且活跃的系统，不扫描卸载区块。

- Curios 专属槽 `gear_heart` 只接受 `kubejs:gear_heart` 与 `kubejs:gear_heart_enchanted`；不可手动取下，死亡保留。
- 玩家每次进入服务器后，登录事件会延后一 tick 检查 `gear_heart` 槽位；空槽自动补发
  一个 `CustomModelData=1`、修复位掩码为 0 的破损齿轮之心，因此七条额度诅咒全部未修复。
  已有物品的槽位不会被替换。
- 未完全修复时提供方块与实体交互距离 +2、急迫 II、夜视 I，造成伤害降低 10%。全链状态改为交互距离 +4、急迫 III、夜视 I，造成伤害提高 50%，不叠加原伤害惩罚；伤害均按小数倍率结算，不取整。
- 急迫与夜视为无限时长，隐藏粒子并保留图标。状态切换会更新既有距离修饰符及本饰品的急迫等级，保留其他来源的更强效果；跨维度继续向重建的客户端玩家重发当前效果与距离属性。旧版齿轮之心施加的虚弱 I 会在效果版本迁移时清除。
- 旧 `CustomModelData=2` 祝福物品会在装备时迁移为受破损态，`DimensionWorksGearHeartRepaired` 按原位保留。
- 修复必须按 1 到 7 顺序使用碎片；第七项完成后物品替换为 `kubejs:gear_heart_enchanted`，进入“全链释限”。
- 完成第二项后在玩家持久数据 `PlayerPersisted.dimensionworks_gear_heart_stage_two` 记录永久里程碑；旧存档装备着已完成第二项的齿轮之心时也会补记。死亡复制该标记，管理员重新启用诅咒不会撤销已完成的里程碑。
- 除转速限额外，齿轮之心额度按 `min(齿轮之心额度, 原模组能力)` 应用；修复或最终释限只能移除齿轮之心额度。转速命令值优先于齿轮之心 RPM 限额。
- 无所有者系统进入共享后备桶，每个仍受诅咒的装备者都要承担共享用量。

管理员可使用统一的 `/dw` 命令管理指定在线玩家已装备的齿轮之心（需要权限等级 2）：

```text
/dw gearheart status <玩家>
/dw gearheart curse clear <玩家> <序号 1-7>
```

`status` 显示七项诅咒的破除进度；`curse clear` 将指定项恢复为未破除状态并立即应用对应限制，转速按首个未修复项之前的连续进度重算，全链个人增益恢复为基础效果。目标玩家必须在线且装备齿轮之心。

### 七阶段

| 阶段 | 诅咒 | 单项修复 | 转速上限 |
| --- | --- | --- | --- |
| 1 | 装备者初始网络 32 RPM | 开始按修复阶段提高转速 | 1,490 RPM |
| 2 | 全部活跃 Create 网络合计 4,096 SU | 立即移除自有 Create 容量额度 | 2,949 RPM |
| 3 | Mek 矿物处理 8 次/秒 | 立即移除矿物处理次数额度 | 4,407 RPM |
| 4 | AE2 自动合成 1 个 | 立即移除自动合成并发额度 | 5,865 RPM |
| 5 | `gear_heart:cross_process` 16 件/秒 | 128 件/秒 | 7,323 RPM |
| 6 | Mek/AE2 活跃设备各 8 台 | 各 64 台 | 8,782 RPM |
| 7 | `gear_heart:final_production` 16 件/秒 | 转换为全链齿轮之心、移除全部工业额度 | 10,240 RPM |

七次修复同时提升转速，按 `round(初始 RPM + (全链 RPM - 初始 RPM) × 连续修复阶段 / 7)` 等分并四舍五入到整数。其他尚未修复的诅咒继续独立生效，修复不会提升原模组实际能力。全链自动取得 10,240 RPM 默认上限。

Create 容量、Mek 处理和 AE2 提交都在真实输出或提交边界先做完整预检；固定间隔令牌桶按玩家与额度类型隔离，同 tick 的多类请求原子提交，拒绝时不消耗输入或令牌。Create、Mek 和 AE2 白名单最终产物在空间模拟通过后才申请第七项额度。

Mek 直接机械供能接受正反两个方向：有效速度按 `abs(RPM)` 收口，Mekanism 机器应力按 `abs(RPM) × 256` 计算，零转速不供能。该行为由 `dimensionworks-mek-stress` 的 `MachinePowerMath` 与输出 Mixin 覆盖。

### 运行边界与验收状态

随机攻击、产出失败、冻结和夜晚饥饿配置已删除；不再取消玩家操作或吞入输入。当前版本的本地构建、82 项 JUnit、32 项 Forge GameTest、75 项仓库脚本测试，以及 JSON/TOML、语言引用、清单版本、任务依赖、配方 ID 和 `git diff --check` 均通过。完整整合包的客户端视觉、双人隔离、任务界面和 JEI 配方仍需游戏内验收。

## Create 全局转速上限

Create 自身还会用 `kinetics.maxRotationSpeed` 钳制所有动力方块，默认只有 256 RPM。
本模组会在每个存档的 `create-server.toml` 加载时检查这个值；低于 10240 时直接修正运行时配置值，
因此已有存档被 Forge 回落到默认值、或新世界配置缺少该键时，都不会再把实际转速卡在 256。
随包仍提供 `defaultconfigs/create-server.toml`，让新建世界第一次加载前就使用正确值。


## Create 动力网络性能优化

> **状态：实现与验证已完成。** 通过 RPM/Mek/应力表单元测试、Forge GameTest 和两轮全新隔离世界性能复测；本改动未作为整合包正式发行。

本 Mod 通过 Mixin 为 Create 6.0.8 的动力网络维护可失效的增量统计缓存：

- 普通成员转速变化时，尽可能只修正该成员的应力贡献。
- 网络结构变化、区块实体移除或无法确认缓存有效时，丢弃缓存并回退到完整核算。
- 普通缓存失效不再伪装成区块加载恢复；只有静默恢复成员才保留“数值没变也要同步一次”的标记。
- 失效时保留旧贡献表并用有效标记拒绝读取，避免对大型 WeakHashMap 反复执行全表 `clear()`；真实重建时再替换表。
- 容量缓存保存的是应用齿轮之心额度前的自然容量；玩家额度仍在返回边界应用。
- Create 容量配额保留每网络的所有者样本，并用 UUID 直接读取聚合总量；常规容量查询不再遍历其他网络样本。样本变更按差值维护总量，服务端 tick 清理阶段会核对仍加载的网络并清除失效样本。
- 所有者改归属即使没有改变 RPM，也会失效并重算该网络的配额样本。
- 每次 Create 应力或容量变化仍立即更新权威总值；若全网的过载标志没有翻转，成员快照合并到本 tick 末发布。跨入或退出过载会在当前调用内同步所有成员，保证机器立即停机或恢复。
- 上次完整成员同步后的过载态会单独记录。已知网络结构下，判断是否跨过过载阈值只比较即时聚合值，不再为每次变化扫描全部成员；结构变更和恢复加载会使标记失效，首次保守校验仍检查成员。
- 显式动力传播和多轴容量事务在事务结束时同步一次。独立动力源同一网络调速时保留网络成员账目，避免 Create 先全网移除再重新加入；分支改变网络 ID 或失去动力源时仍使用 Create 的正常移除路径。
- 不重写 Create 的转速传播图，也不修改或分发 Create 源码。

该改造将 4096 成员网络的 100 次顺序应力变化从 100 次全网同步收敛为 1 次；必要的成员同步仍是 O(N)。失效的容量样本仍可能触发一次完整 source 扫描；重启或区块加载时，每个恢复网络至多额外同步一次。完整轴链调速仍须遍历成员以更新各自转速。若附属在同一调用中依赖成员的非阈值 stress/capacity 快照，可在自己的边界调用 Create 的 `network.sync()`。本测试不是完整整合包或玩家工厂 TPS 证明，隔离性能对照见 `docs/validation/kinetic-lab/report.md`。

超速倍率在 `KineticNetwork#getActualStressOf` 的实际应力边界动态应用，`network.members` 只保存速度无关的基础 impact，因此速度断点、玩家 RPM 上限和附属发电机变速后不会继续沿用旧应力系数。未结束的异常批次会在服务器 tick 末保守收束；普通延后快照也在 tick 末统一发布，单个网络刷新异常会被隔离并记录。

恢复 Create 从区块数据静默重建的网络成员后，RPM Limit 会安排该网络在下一 tick 完成一次成员同步。即使重算后的容量和应力总值与存档相同，也会重新应用各机器的超载状态，避免旧的超载标记在重启后让整个网络持续停转。若网络实际仍然超载，同步后仍会正确停机。正常的网络重算已执行同步时不会重复同步；每次网络区块恢复最多额外进行一次全网同步，不增加每 tick 的常驻扫描。

### 所有权与额度边界

- 已识别所有者的网络中，无直接所有者的中继继承网络最低上限；完全无法识别所有者的网络，实际工作转速回退到保守默认 RPM。
- 已经由其他自研适配器收口转速的虚拟成员通过 `IPreclampedKineticSpeed` 跳过二次限速。
- Gear Heart 的 Create 容量按每个 source 的实际容量与所有者分别分桶；混合所有者网络不会整体归给第一个活跃成员。
- 速度控制器只在原存档缺少所有者时补写发送者，不覆盖既有所有者。

## Command
Requires permission level 2:
```
/dw rpm <player> <limit>
```

This changes the target player's RPM limit for Create kinetic networks they own.

## 每台机械上限

玩家放下动力方块时，方块会记录直接拥有者，并同步保存该玩家当时的 RPM 上限。上限变化后，
模组会立即扫描所有已加载维度中该玩家直接放置的动能方块，更新机器上限并同步给客户端；
未加载区块会在下次加载时读取玩家最新上限。

齿轮、大齿轮和速度控制器仍使用 Create 原生倍率计算，但每次 Create 写入动能方块转速时，都会
按该方块所有者的个人上限封顶。因此齿轮链的每一级存储转速、理论转速及消费者实际转速都不会
超过其所有者上限；齿轮倍率不能继续叠加出超限转速。修改个人上限时，已加载的自有动能方块会
立即重新收口，未加载区块在加载时收口。不同玩家混合的网络按每台方块的直接所有者分别限速。
应力容量与应力消耗也按同一个有效转速缩放，避免只看原始网络速度时把限速后的机器误判为过载。

## KubeJS
Server-side KubeJS can call the public Java API:
```js
const RpmLimitApi = Java.loadClass("dev.szx.dimensionworks.rpmlimit.RpmLimitApi")

// ServerPlayer -> limit
RpmLimitApi.setLimit(player, 64)
const limit = RpmLimitApi.getLimit(player)

// UUID string -> read limit
const limit2 = RpmLimitApi.getLimit(player.uuid.toString())
```

Values are clamped to 1..10240. This API changes the player's stored limit immediately and refreshes all currently loaded machines owned by that player, including their stored network speeds.

## 超速并行（Overspeed Batch）

转速超过机器自身的饱和点后，同一次操作会按倍数并行处理多份原料与产出。
512→10240 RPM 的空转区间因此变成真实产能，但应力会随倍数同步放大，想超速多产就必须多堆发电机。

比例 `r = 当前 RPM ÷ 该机器饱和点`，阶跃取值，全局封顶 15×：

| r | 1 | 2 | 4 | 8 | 10 | 12 | 14 | 16 | 18 | 20 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 倍数 | 1× | 2× | 2.5× | 3.5× | 5× | 7× | 8.5× | 10× | 11.5× | 15× |

换算到实际转速：

- 搅拌机、机械压力机（饱和点 512）：512 / 1024 / 2048 / 4096 / 5120 / 6144 / 7168 / 8192 / 9216 / 10240 RPM 对应上表。
- 风箱（256）：断点转速减半，2560 RPM 起达 5×，5120 RPM 到顶 15×。
- 动力锯（3072）：10240 RPM 时只到 2×。
- 磨石（8192）：10240 RPM 时仍是 1×。

小数倍数用确定性余量累积实现：2.5× 表现为交替 2 份、3 份，长期平均 2.5，不使用随机数，
也不额外同步任何字段。工作批次只在机器原本完成一次配方/加工的位置重复执行对应入口，不重跑完整的 `tick()`；
原料、产出、概率产物、流体仍走 Create 原生逻辑，原料不足时自然降为可用份数。

渲染侧使用另一条路径：Flywheel 与非 Flywheel 动画都会把视觉转速限制在该机器自身饱和点。
因此超出饱和点后动画保持原来的最高速度，只有加工倍率和应力继续增长。

纯传动与物流设备（轴、齿轮、传送带、溜槽、机械臂、活塞、绳索、火车、显示器）、钻头与动力泵本轮不参与。
风箱只重复物品处理（`AirCurrent#tickAffectedHandlers`），不重复推动玩家与生物的 `tickAffectedEntities`。

### 护目镜

倍数大于 1 时，护目镜在原有信息后追加一行“超速并行 ×N”；倍数为 1 时不显示，保持原版观感。
倍数由客户端用同一张表从自己看到的转速推算，不需要额外网络包。

### 配置（COMMON，`[overspeed]`）

| 键 | 默认值 | 说明 |
| --- | --- | --- |
| `enabled` | `true` | 超速并行总开关 |
| `cap` | `15` | 全局倍数上限 |
| `stressScaling` | `true` | 应力是否随倍数放大 |
| `stepTable` | `1:1,2:2,4:2.5,8:3.5,10:5,12:7,14:8.5,16:10,18:11.5,20:15` | 断点表，解析失败时保留旧表并记日志 |
| `defaultSaturationRpm` | `512` | 白名单机器未登记饱和点时的回退值 |
| `classWhitelist` | `[]` | 额外参与批处理的方块实体类名（全限定名或简单名） |

### 附属机器

附属机器默认不参与，保持 1×。确认某台附属加工机适合批量后，把它的类名加进 `classWhitelist` 即可，
饱和点用 `defaultSaturationRpm` 或按需在后续版本登记。Create: Diesel Generators 的盆盖继承盆式加工链，
会自动跟随搅拌机一类机器生效。

### 已知取舍

- 置物台冲压走 `BeltPressingCallbacks`，会在一轮动画内聚合多份原料和产出；原版回调无论输入堆多大都只消耗 1 个。地面物品另走 `applyInWorld()`，两条路径都已按倍率处理。
- 动力锯受单个输入槽限制，原版在饱和转速附近已经达到每 tick 一个堆栈的处理上限；超速不会额外复制输入。
- 倍数使用玩家上限后的有效转速，但直接读取原始理论转速再封顶，避免过载时掉回 1× 造成应力抖动。
- 视觉转速上限只影响渲染器，不参与配方、应力或网络速度计算。

## 高级转速控制器（0.4.9）

0.4.11 起，控制器界面额外显示设备所有者的实际生效上限；`/dw rpm <player> <limit>` 的反馈同时显示基础值与生效值。命令设置的 RPM 上限优先于齿轮之心的阶段限额：第一阶段默认 1,490 RPM，命令设为 10240 RPM 后仍按 10240 RPM 生效；命令设为 128 RPM 时也不会被修复抬高。其他来源的外部上限仍可进一步收紧有效值。未显式设置命令上限时，在线玩家与离线存档均按当前连续修复阶段恢复默认值，全链提升到 10,240 RPM。界面中的生效值在打开时读取。

新增 `dimensionworks_rpm_limit:advanced_speed_controller`，继承 Create 转速控制器的传动行为，直接引用其外观资源。右键输入整数后回车或 Esc 退出即应用；负数反转，0 停止，非法输入保留旧值。默认目标范围 ±10,240 RPM，实际输出继续受所有者命令上限、其他外部限制及仓库硬上限约束；齿轮之心转速限额低于命令设置。原滚动数值框隐藏。

KubeJS 配方 `dimensionworks:advanced_speed_controller` 使用 25 个动力合成器，中心为原版转速控制器。材料与第二项诅咒的软门槛见[设计文档](../../docs/design/advanced-speed-controller.md)。不使用配方解锁或诅咒状态检查。

服务端检查菜单、操作距离、区块状态和数值范围，不强加载区块，不增加常驻扫描。尚未进入游戏验证 UI、渲染、传动及多人行为。

### 0.4.12：重启后的动力网络状态恢复

Create 从区块数据通过 `addSilently` 重建网络成员后，会把网络标记为待刷新，并在首个成员 tick 中完成一次正常网络重算。如果 Create 发现容量和应力总值未变化、因此跳过通常的成员同步，RPM Limit 会补做一次同步，重新计算已加载机器的超载状态。若网络确实超载，机器仍会停转；常规网络更新已经完成同步时不会再次同步。每次恢复的网络最多一次成员同步，不增加每 tick 扫描。

验证：Forge GameTest 在真实 Create 服务器中通过方块放置 API 构造动力网络，并调用 Create 的静默网络恢复入口，覆盖“成员状态为超载、重算总值不变但实际未超载”时恢复运转，以及“实际仍超载”时继续停机。共 10 项必需 GameTest 全部通过，构建与单元测试也通过。

### 0.4.10：动力传播限幅一致性

修复高级转速控制器目标值超过接收方 RPM 上限时，接入动力会造成 `StackOverflowError` 的问题。Create 在 `RotationPropagator.propagateNewSource:261` 使用未限幅的传播预测反复尝试提高转速，但 `setSpeed` 每次都将存储值压回玩家上限，因而无法收敛。现在在 `getConveyedSpeed` 返回处使用与写入网络速度相同的接收方限幅规则，使正反向传播预测与实际存储值一致。原版转速控制器及超限齿轮传动也受同一规则保护。目标值仍可保留为更高数值，实际速度继续遵守齿轮之心限制，不清除世界或设备数据。

独立 Forge GameTest 源集位于 `src/gameTest/`，不会包含在发布 JAR 内。运行 `gradle runGameTestServer --no-daemon -x downloadAssets` 可验证大齿轮输入、传动轴输入、正反转、零速、上限内调速及原版控制器超限。`downloadAssets` 是无界面服务器不需要的客户端资源准备步骤。开发运行时补齐整合包已有的 GuideME 依赖，未向整合包新增模组。

验证：修复前 Forge GameTest 复现了服务器相同位置的 `StackOverflowError`；修复后六项游戏测试全部通过，结果见设计文档。尚未在生产服应用此次修复。

## 0.4.14：应力恢复账目与网络拓扑诊断

- 同一动力网络采用已接入真实参与者中最低的个人 RPM 上限，统一限制有效转速及实际应力/容量。虚拟成员继承其接入端的有效转速，不额外引入一个虚构所有者上限。网络连接变化或个人上限变化后重算；低上限成员移除后解除其约束。传动图仍使用每台机器原有理论转速与齿轮倍率，避免破坏 Create 的传播一致性。
- 保留齿轮之心 SU 容量额度。网络容量样本变化、归零或移除后，其他网络在 tick 末重新分配，避免恢复顺序固化额度。
- `DWKineticAccounting.Version=1` 保存额度限制前的物理成员自然容量、实际负载、物理成员数，以及本机保存时的实际贡献。恢复按保存贡献精确扣账，不再用基础 impact 猜测超速后的贡献。虚拟成员负载不写入恢复总账，重新接入时只计费一次。
- 无此格式的旧存档保留转速与 source 连接，丢弃无法区分真实/虚拟/残留的旧总账，随区块加载重新登记成员。未加载旧区块的单机贡献无法从旧总数准确反推，加载前不会伪造其贡献；需要完整检查的旧工厂应让相关区块正常加载后再核对。
- 蹲下，主手持 Create 扳手或带 `forge:tools/wrenches` 标签的工具，左键动力方块打开只读 GUI；本次点击不破坏方块。Mek Stress 适配的 Mekanism 机器也可作为入口，无动力连接时提示未接入网络。
- 图中展示服务端 source 传播树（含有明确接入端的虚拟成员连接）、坐标、理论/实际转速、个人/网络 RPM 上限、单机应力/容量、超载状态，以及网络当前总数和未加载余额。支持拖动、滚轮缩放、点击节点、右侧详情滚动、分页与手动刷新。每页 256 节点，不静默截断整个成员表；跨页上游在详情中显示坐标。
- 图是按需快照，不自动每 tick 扫描，也不强制加载区块。未加载成员只有总账，不能据此声称已知道其全部连接；source 树不等于所有物理可传动边。诊断不触发应力重算。

自动回归增加实际 NBT 账目往返、超速贡献、虚拟成员排除和最低上限成员移除场景；GameTest 在 GitHub Actions 运行，本机不构建。图形交互仍需客户端实测。

## 0.4.19：齿轮之心跨维度效果同步
